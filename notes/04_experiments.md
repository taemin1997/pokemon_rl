# 04. 보상 설계 실험 기록

## 공통 조건 (바꾸면 여기에 적기)
- 시작 상태: `states/start.state` (리아코 받은 직후, 집 1층 24:6 (9,2))
- 행동: 상하좌우 + A + B (START/SELECT 제외), 1스텝 = 24프레임
- 관찰: 화면 흑백 72x80
- 에피소드: 최대 2048스텝, 배지 1개 획득 시 종료
- PPO: CnnPolicy, 환경 6개, n_steps 512, batch 256, epochs 4, gamma 0.995, ent_coef 0.01, lr 2.5e-4, seed 0
- 속도: 학습 포함 약 230스텝/초 → 100만 스텝 약 1.2시간 (CPU)

## 기준점: 랜덤 행동
| 항목 | 값 |
|---|---|
| 1000스텝 보상 | 3.6 |
| 탐험 칸 | 37 |
| 맵 | 1 (집 밖으로 못 나감) |

- 주의: 위 값은 1000스텝 기준이라 2048스텝 에피소드와 직접 비교가 안 됨
- 실제 기준점은 v1 학습 첫 기록(12k 스텝, 거의 랜덤 상태)인 **visited_maps 2.83**으로 보는 게 맞음
  (집 1층, 2층, 마을 정도는 2048스텝이면 랜덤으로도 들어감)

### A_route29 (29번도로 커리큘럼, 250k pilot)
- **바꾼 것**: 환경 (`--env route29`). 보상, PPO 설정은 v1 그대로
  - 시작: S1_entry (29번도로 입구, 무궁시티까지 90걸음)
  - 29번도로 밖으로 나가면 실패 종료 (마을, 화이트아웃으로 집)
  - 무궁시티 도착하면 성공 종료
  - 전투는 A 연타로 자동 처리 (확인: 58전 57승, 전투당 약 2550프레임)
  - 최대 512스텝
- 환경 변경 묶음이라 엄밀히는 여러 요소를 같이 바꿨음. 다만 전부 "29번도로만 떼어서 보기" 하나의 목적이고, 보상/관찰/PPO는 그대로 둠
- **가설**: 막힌 원인이 H4(마을 복귀 습관) + H5(풀숲 전투 비용)라면, 둘을 환경에서 제거했을 때 풀숲을 건너 (43,14) 출구로 나가는 법을 배울 것
- **기준선** (`diagnose_route29 --auto-battle`, 같은 조건)
  - random: S2에서 탈출 4%, S1/S3 0%. 진행 평균 S1 6.0 / S2 3.8 / S3 6.5
  - v1 final: 전부 마을 복귀 100%, 탈출 0%
- **판정 기준** (250k 후 진단 평가로)
  - S1 탈출률 > 30% → 가설 지지, 1M까지 연장
  - 탈출률 ≈ random 수준(0~4%)이지만 진행이 늘어남 → 방향은 맞는데 신호 부족 → 실험 B (거리 shaping)
  - 진행도 random 이하 → 탐험 보상 자체가 29번도로에서 제대로 작동 안 함 → 보상 구조 재검토
- **해석할 때 조심할 점**
  - 이탈 = 종료라서, "29번도로에 오래 머물기만" 해도 판 길이가 늘어남. 진행(거리)으로 판단해야 함
  - 전투가 자동이라 이 정책은 전투를 못 함. 나중에 합칠 때 따로 검증 필요
- **결과**: ❌ **무효 (환경 버그로 인한 reward hacking)**, 61k에서 중단
  - 증상: 풀숲에 거의 안 들어감. 9k~39k 구간에서 이탈률 100%, 판 길이 5~30스텝, 판당 보상 약 1.1
  - 원인: 29번도로 밖(마을)으로 나가는 걸음에 "처음 들어간 맵 +1.0"이 붙었음
    → "입구에서 동쪽으로 몇 걸음 나가기 = +1"이 새 칸 10개를 밟는 것과 같은 값인데 훨씬 쉬움
    → 에이전트가 정확히 그걸 배움 (보상 함수를 잘 공략한 것이지, 게임을 잘한 게 아님)
  - 수정: 허용 구역을 벗어난 걸음은 보상 0 (`gold_env.py` step). 나가는 걸음 보상 0.0으로 확인
  - 참고: 버그가 있었는데도 46k 이후엔 이탈률이 17~75%로 떨어지고 진행이 13~14까지 늘었음 (random 6)
  - 교훈: **종료 조건을 만들 때, 종료되는 그 걸음의 보상도 같이 확인해야 함**. "끝나니까 손해"라고 생각했지만, 끝나는 순간의 보상이 더 컸음

### B_route29 (A2 + 거리 shaping)
- **바꾼 것**: 보상만 (`--reward B_progress`). 환경은 A2와 같은 `--env route29`, PPO 설정도 동일
  - 추가 보상 = 0.1 × (이전 남은 거리 − 지금 남은 거리). 거리표에 없는 칸(점프 중간)은 건너뜀
- **구현 확인** (학습 전)
  - 제자리 B 연타 50걸음: shaping 0.00
  - 좌우 왕복 100걸음: shaping +0.10 (순이동 1칸만큼) → 농장 불가
  - 마을로 이탈: 보상 0
  - 정답 경로 따라가기: 185걸음 만에 도착, shaping +10.30 (= 0.1 × 103 정확히), 전체 보상 +21.7
- **가설**: A2가 U턴 이후에서 멈추는 이유가 "그 구간에 방향 신호가 없어서"라면, 거리 감소를 보상하면 무궁시티 도착이 생길 것
- **비교 대상**: A2_route29 250k (같은 학습량). 진단 평균 진행 S1 55, 무궁 0%
- **판정 기준** (250k 후 `diagnose_route29 --auto-battle`, A2와 같이 돌림)
  - 무궁시티 도착률 > 0%이고 진행 평균 > 55 → shaping 효과 있음
  - 진행은 늘었는데 도착 0% → 남은 구간에 다른 장애물이 있음 (위치 분석)
  - A2와 차이 없음 → 방향 신호가 병목이 아님 (학습량 문제 → A2 연장으로)
- **해석할 때 조심할 점**
  - 거리표는 **정답 지도(oracle)**. 잘 되면 "길을 찾았다"보다 "거리 신호를 따라갔다"에 가까움 → 나중에 shaping 없는 A2와 나란히 보여줘야 정직함
  - 거리표는 근사값 (같은 시작 상태로 BFS를 두 번 돌려 115/128이 나옴). 표가 틀린 곳에선 잘못된 신호가 감
  - `shaping_sum`은 항상 0.1 × (시작 거리 − 마지막 거리)여야 함. 아니면 버그
- **순서 메모**: A2 사전 기준은 "1M 연장"이었지만, 같은 250k 예산에서 B와 먼저 비교하고 나서 더 나은 쪽을 연장하기로 바꿈 (예산 효율)
- **결과** (250k, `final.zip` 기준. `train.diagnose`, 위치당 25판)

### A3_route29 (A2 + 도착 보너스, BFS 없음)
- **바꾼 것**: 보상만 (`--reward A3_goal`): A2 보상(새 칸 0.1, 새 맵 1.0) + 무궁시티 도착 +10. 거리 보상 없음

  - 덜 해본 자리 우선순위 1.0 → 0.5
- **구현 확인**: 무작위 행동 40판 후 아카이브 14개, 목표까지 거리(분석용) 1~8에 고르게 → 실력 있는 곳 주변으로만 넓어짐 (AC는 같은 조건에서 181개, 1~104). 후보 시작 도착 46%
- **가설**: 아카이브가 실력 경계를 따라 넓어지면, 연습 판 도착률이 적당히(20~80%) 유지되면서 전선이 입구 쪽으로 이동
- **판정 기준** (250k, `train.diagnose route29`): S1 도착 ≥ 30% → 분기점 통과 / `start_dist` 중앙이 U턴(약 50) 너머로 감 → 연장 / 전선 정체 → 넣는 규칙 완화
- **볼 지표**: `real_goal`, `start_dist`(이번엔 전선 역할), `reached_goal`(연습 판 도착률이 20~80%에 머무는지), `rc_pool`
- **결과**: ❌ 정체 (126k 학습 지표 + 200k 체크포인트 진단)
  - 학습 지표: 연습 판 도착률 91% (너무 쉬움), 전선 `start_dist` 4.5, 아카이브 20개에서 거의 안 늘어남, 실제 입구 도착 0%
  - 진단 (`ppo_199992_steps`, 실제 시작 상태, 위치당 25판)

- **해석**
  - **목표 근처에서만 배운 정책은 그 밖에선 길을 모름**: 실제 시작에선 random보다 조금 나은 정도
  - 실패는 거의 전부 **전멸**: 판당 전투 7~8번. 도착 보상밖에 없으니 풀숲을 피할 이유가 없고, 512걸음 동안 풀숲을 헤매다 쓰러짐
  - 정체 원인: 잘하는 자리에서 시작하면 에이전트가 곧장 목표로 가버려서(약 9걸음), 그 판들이 밟는 자리는 이미 아는 목표 쪽뿐 → **실력이 생길수록 바깥 자리가 안 생김**
- **RC → AC2 종합**: 후보를 무작위로 만들면 느리고(RC, RC2), 아무 자리나 쓰면 너무 어렵고(AC), 잘하는 판에서만 모으면 안 넓어짐(AC2) → **모으기(넓게)와 고르기(실력 경계 바로 바깥)를 분리해야 함**

### AC3_route29 (공간 전선: 넓게 모으고, 실력 경계 바로 바깥에서 고르기)
- **바꾼 것**: 시작 위치를 고르는 방식만 (보상 `goal_only`, PPO 그대로, 거리표 안 씀)
  - 모으기: AC와 같음 (모든 판에서 처음 밟은 좌표, 최대 400)
  - 익힌 자리(anchor): 성공률 80% 이상. 아카이브에서 빠져도 좌표는 기억
  - 고르기 가중치: 전선(익힌 자리에서 같은 맵 좌표로 6칸 이내, 아직 못 익힘) 1.0 (해봤는데 20% 미만이면 0.3) / 익힌 자리 0.1 / 먼 곳 0.02 / 익힌 자리가 없을 땐 씨앗 1.0. 모두 ÷ √(뽑힌 수 + 1)
- **장치 확인 (학습 없이)**: 이미 잘 가는 B2 모델을 넣고 150판
  - 익힌 자리 4(30판) → 12 → 18 → 26 → 33(150판), 최근 연습 위치 중앙 4 → 11 → 17 → 24 → **29**
  - 30판마다 전선이 6~8걸음씩 바깥으로 이동 → 커리큘럼 장치는 의도대로 동작 (RC2, AC2는 10만 스텝 넘게 5걸음에서 정체)
- **가설**: 장치가 전선을 실력 경계로 옮겨주므로, 학습하는 에이전트도 목표 근처부터 실력을 쌓아 입구 쪽으로 퍼질 것
- **판정 기준** (250k, `train.diagnose route29`): S1 도착 ≥ 30% → 분기점 통과 / `rc_anchors`와 `start_dist`가 꾸준히 커지지만 입구까지 못 감 → 연장 / 익힌 자리가 안 늘어남 → 학습 쪽 문제 (보상, 관찰)
- **볼 지표**: `rc_anchors`(익힌 자리 수), `start_dist`(연습 위치 = 전선), `reached_goal`(연습 판 도착률, 20~80%가 정상), `real_goal`
- **결과** (250k, `final.zip`)
  - 학습 지표: 익힌 자리 0 → 23(58k) → 47(147k) → **약 48~50에서 정체(200k~)**. 전선(`start_dist`) 약 50 (U턴 구간)에서 왔다 갔다. 연습 판 도착률 30~50%. 실제 입구 도착 0%. 엔트로피 -1.65 근처 (거의 안 굳음)
  - 진단 (실제 시작 상태, 위치당 25판)

| 시작 | 도착률 | 진행 p50/p90/최대 | 이탈 | 전멸 | 전투/판 |
|---|---|---|---|---|---|
| S1 | 0% | 4 / 5 / 6 | 48% | 0% | 0 |
| S2 | 0% | 5 / 7 / 9 | 56% | 56% | 6.2 |
| S3 | 0% | 0 / 2 / 2 | 36% | 0% | 0 |

- **판정**: 사전 기준의 "꾸준히 늘다 입구 못 감 → 연장"에 가깝지만, 마지막 5만 스텝은 익힌 자리가 **늘지 않고 정체** → U턴에서 다시 막힌 것으로 판단
- **해석**
  - **선생님 없는 방식 중 처음으로 전선이 U턴(약 50걸음)까지 옴** (RC~AC2는 5~9걸음). 모으기/고르기 분리 + 공간 전선이 효과 있었음
  - 그런데 **U턴에서 멈춤**. A2, A3(입구에서 시작)도 진행 약 47에서 멈췄음 → 방향이 반대여도 같은 지점이 벽
  - 추정 원인 (확인 필요): U턴 너머(아래쪽 길, y=14~16)는 익힌 자리와 **좌표로는 가깝지만(4~6칸) 실제 경로로는 멂**(턱 줄 때문에 x=31 틈으로 돌아가야 함). 공간 전선이 "좌표 근처 = 다음 단계"라고 가정하는데, U턴은 그 가정이 깨지는 지형
  - 실제 시작 상태에선 엉망: 진행 0~9, 입구/S3에선 36~48%가 그냥 마을로 나감. 익힌 범위(목표 50걸음 안쪽) 밖은 전혀 모름 → **익힌 범위 밖으로는 실력이 번지지 않는다**는 AC2와 같은 결론
- **다음**
  - **역방향 시연 학습** (Go-Explore 2단계 방식): 탐색이 찾은 경로 위에서 시작 위치를 고름 → 전선이 좌표가 아니라 **경로를 따라** 이동하니 U턴 가정 문제가 없음. 보상은 도착만, 버튼은 안 따라 하게 함 (RL)
  - 비교용으로 AC3 연장(500k)은 우선순위 낮음 (정체 근거가 있음)

### DEMO_route29 (역방향 시연 학습: 전선이 좌표가 아니라 경로를 따라 움직임)
- **바꾼 것**: 시작 위치를 고르는 방식만 (보상 `goal_only`, PPO 설정 그대로, 거리표는 학습에 안 씀)
  - 시연: `build_segment route29 --demo`가 거리표를 따라 걸으며 지나간 칸의 상태 103개를 저장 (`states/segments/route29/demo.pkl`). 최단 경로와 같음 (남은 거리 103 → 1, 한 번도 안 늘어남). 전투는 타이밍을 바꿔 피함 → HP 18~20 (실제 입구 20)
  - 전선(ptr): 시연 번호. 판 시작은 [ptr, ptr+4] 중 무작위, 10%는 실제 입구
  - 당기기 (`DemoCurriculumCallback`): 롤아웃(3072스텝)마다 환경 6개 결과를 모아서, 전선 구간에서 시작한 판이 24개 이상이고 도착률 ≥ 50%면 ptr을 3걸음 입구 쪽으로. **전선 하나를 환경 6개가 같이 씀** (AC 계열은 환경마다 따로였음)
- **비계 명시**: 시연 경로는 BFS(거리표)가 찾은 것 = **선생님이 정답 경로를 한 번 보여준 것**. 다만 버튼(행동)은 안 주고, 보상/관찰에도 안 들어가고, "어디서 연습할지"에만 씀. 각 시작점에서 어떻게 걸을지는 RL이 도착 보상만으로 배움
  - 그래서 성공해도 결론은 "선생님 없이"가 아니라 **"매 걸음 방향 신호(B2) 대신 시연 1개 + 도착 보상으로 U턴을 넘음"**
- **장치 확인 (짧은 시험 9천 스텝)**: 전선 1 → 4 → 7걸음 (롤아웃마다 3씩), 전선 구간 도착률 85~100%, 실제 입구 도착 0%. 저장/이어서 하기 동작
- **가설**: AC3가 U턴에서 멈춘 원인이 "좌표 근처 = 다음 단계" 가정이라면, 전선이 경로를 따라 움직일 때 U턴(경로상 목표에서 약 50~68걸음: (40,8) → x=31 틈 → (33,16))을 지나 입구까지 갈 것
  - 반대로 U턴 구간에서 도착 보상만으로는 배우기 자체가 어렵다면(예: 턱 줄 아래에서 목표 반대 방향 서쪽 → 틈 → 동쪽), 전선이 경로를 따라가도 약 50~68에서 멈출 것
- **비교 대상**: AC3 250k (전선 약 50에서 정체, 입구 도착 0%, 진행 p50 0~5) / B2 (거리 보상) 88~96%
- **판정 기준** (250k, `train.diagnose route29`, AC3와 같은 진단)
  - S1 도착 ≥ 30% → 분기점 통과 (시연 1개 + 도착 보상으로 U턴을 넘음) → 시드 재확인 + 일반화 시험
  - `demo_front`가 70 이상(U턴 아래쪽 길 너머)으로 갔지만 S1 도착 < 30% → 방향 맞음, 학습량 부족 → 500k 연장
  - `demo_front`가 50~68(U턴 구간)에서 5만 스텝 넘게 정체 → **커리큘럼 방식이 아니라 U턴 자체가 도착 보상만으로 어려움** → U턴 미니 벤치마크(U턴 앞뒤 시작점만 떼서 시험)로 원인 분리
  - `demo_front`가 50도 못 감 (AC3보다 느림) → 당기기 규칙 문제 (min_eps, 성공 기준) → 조정
- **볼 지표**: `demo_front`(전선, 경로상 목표에서 몇 걸음), `demo_front_rate`(전선 구간 도착률, 50% 근처면 정상), `real_goal`, `start_dist`(분석용)
- **해석할 때 조심할 점**
  - 시연 상태는 고정된 103개라, 그 상태들(난수, NPC 위치 포함)에 맞춰 외울 수 있음 → 평가는 반드시 실제 시작 상태 진단(시작 프레임 흔듦)으로
  - 경로 밖으로 벗어난 상황은 연습이 적음 (시작이 전부 최단 경로 위). 실제 시작에서 한 번 벗어나면 회복을 못 할 수 있음 → 진단의 진행 p50/p90과 이탈로 확인
- 학습 중 관찰 (13.5만, 전선 64 = 턱 줄 아래 (31,14)~(33,16))
  - 전선 판 6번 중 5번이 **(27,10)에 갇혀 512걸음 끝까지 위/오른쪽/아래로 벽을 밈** (막힌 이동 약 90%, A/B 약 30%). 1번은 221걸음에 도착

- 학습 중 관찰 2 (16만, 전선 67): **제자리 회전** (사용자 관찰 "팽이처럼 돎")

  - 추정: 윗길에서 배운 "동쪽으로 가다 x=40에서 북쪽"을 화면이 비슷한 아랫길에서 반복 (확인 안 함)

### DEMO_TILE_MEM_route29 (DEMO_TILE + 짧은 기억)
- **바꾼 것**: 관찰만 (`--memory`). 화면에 숫자 7개를 붙임: 직전에 누른 버튼(원핫 6) + 직전 걸음에 실제로 움직였나(1). 커리큘럼, 보상, 조작(tile), PPO 설정 그대로

- **구현 확인**: 왼쪽 벽 두 번 → 기억 [left, 안 움직임], 위로 세 번 → [up, 움직임], A → [a, 안 움직임]. 판 시작은 전부 0. 2개 환경 짧은 학습 동작
- **가설**: 갇힘의 원인이 "막힌 걸 모름"이라면, 기억을 주면 연속 막힘이 짧아지고(막힌 직후 같은 행동 확률 감소), 갇히는 판이 줄어 같은 스텝에서 전선이 더 멀리 감
- **비교 대상**: DEMO_TILE 250k (같은 진단 실행에서 나란히)
- **판정 기준**
  - 확인용 (행동): 막힌 직후 같은 버튼을 또 누르는 비율, 판별 최장 연속 막힘이 DEMO_TILE보다 확실히 줄어야 함. 안 줄면 정보를 안 쓰는 것 → 기억 형태 재검토 (프레임 쌓기 등)
  - 주 기준: 같은 스텝에서 `demo_front`가 더 멀리 감 / 입구 도착률 +10%p 넘게 → 기억 유지. 이후 실험 기본값
  - 막힘은 줄었는데 전선 차이 없음 → 갇힘은 병목이 아니었음 → 당기기 속도 등 다음 후보로

  - CHAIN1 (ii): 28%, 실패는 전부 시간 초과 (이탈 0, 전멸 0), 진행 p50 68 = 29번도로 약 44걸음 = U턴 근처 → **연두마을을 배우면서 29번도로 U턴을 잊음** (catastrophic forgetting)
- **해석**
  - 가중치 이어받기는 이 조건에서 "능력 이전"이 아니라 "습관 이전". 29번도로에서 굳은 정책(엔트로피 낮음)은 새 장소에서 막히면 다른 방향을 덜 시도함 → 돌아가야 하는 자리(문 밖, 집 안 모서리)에서 오래 정체
  - 그리고 새 구간을 배우면 옛 구간을 잊음. 둘 다 "한 구간씩 차례로 이어 학습"이 안 맞는다는 근거 → **여러 구간 섞어 학습**(같은 롤아웃에 연두마을 판과 29번도로 판을 같이)으로 가야 "모델 하나가 여러 구간을" 원칙을 지킬 수 있음
  - 이어 붙이기 96%는 구간 경계에서 모델을 바꾸는 사람의 상위 계획(구간 순서)이 비계. RL: 각 구간 안의 걷기 전부
  - 시드 1개, 이 비교는 짧은 구간 하나라 일반 결론은 아님. 다만 차이(24 vs 100%, 28 vs 96%)는 오차(±10%p)보다 훨씬 큼
  - 주의: init29 평가는 7.4만 모델이라 scratch 10만과 스텝이 다름. (ii)를 10만으로 다시 재도 U턴을 잊은 건 연두마을 학습 중에 생긴 일이라 결론은 같을 것으로 봄 (확인하려면 `--resume latest --total-steps 100000`)

### OFFPATH1 (학습 없음: 경로 일반화 진단 — "줄을 외웠나, 길을 배웠나")
- **왜**: DEMO_TILE은 학습 중 모든 판이 시연 경로 위에서 시작함. 진단 S2/S3도 경로 근처라 "경로 밖에서도 되나"를 잰 적이 없음. 29번도로 모델을 집 1층에 넣으면 진행 p50 2(무작위 5)였던 게 "상태 분포에 묶인 정책"의 신호. MIX1, 목표 정보보다 먼저 이걸 재야 다음 실험 방향이 정해짐 (외부 검토 의견 반영)
- **도구**: `train/offpath.py` (새로 만듦)
  - `build route29`: 시연 상태 103개에서 BFS로 걸어 나가며 칸마다 상태 저장 (전투 피하는 타이밍 → HP는 시연과 같은 18~20). 29번도로 485칸 중 483칸. 경로에서 거리별: 0 = 103, 1~2 = 182, 3~5 = 128, 6~9 = 59, 10+ = 11
    - 경로에서 거리 = 시연 경로 칸에서 앞으로 걸어서 몇 걸음 (턱 일방통행 반영)
  - `eval`: 경로 거리 구간(1~2 / 3~5 / 6~9 / 10+)마다 off-path 칸 8개를 목표 거리 순으로 고르게 골라서, 칸마다 **목표 거리가 가장 비슷한 경로 위 칸을 짝**으로 같이 돌림 (칸당 4판). 같은 목표 거리에서 "밖 − 짝" 차이 = 경로에서 떨어진 효과. 목표가 멀거나 지형이 어려워서 생기는 차이와 분리
  - `perturb`: 입구에서 정상 출발 → 목표까지 남은 거리가 80/50/25 이하가 되는 순간, k(3, 6)걸음 안에 갈 수 있는 칸 중 경로에서 가장 먼 칸으로 강제로 끌고 감 → 정책에게 돌려줌. k=0이 기준. 조건당 25판
    - 주의: 29번도로는 경로가 구불구불해서 k=6이어도 경로에서 3~5칸까지만 떨어짐 (지형 한계). 그래서 "실제로 밀린 거리"를 같이 기록. 먼 거리는 eval이 담당
- **비교**: DEMO_TILE (시드 0, 1), B2 (거리 보상)
  - B2는 매 걸음 거리 신호를 받았고, 시작은 입구 고정이었지만 자기가 헤맨 자리에서도 신호를 받음 → 경로 밖에서 강할 것으로 예상
  - **혼동 주의**: B2는 tap 조작이라 DEMO_TILE과 조작이 다름. "B2가 경로 밖에서 더 좋다"가 나와도 보상 차이인지 조작 차이인지는 이 실험만으로 못 가름 (tap이 불리한 쪽이라, B2가 이기면 보상 쪽 근거로는 오히려 보수적)
- **판정 기준** (결과 보기 전에 정함. 25판 오차 ±10%p → 칸 8 × 4판 = 32판도 비슷하게 봄)
  - ① DEMO_TILE의 "밖 − 짝" 차이가 거리 따라 커지고 6~9 / 10+에서 −30%p 넘게, B2는 −15%p 안쪽 → **학습 분포가 좁은 문제** → 다음 실험은 경로 옆 시작 (폭도 넓히는 2차원 커리큘럼)
  - ② DEMO_TILE, B2 둘 다 −30%p 넘게 떨어짐 → 보상/커리큘럼 문제가 아니라 관찰/신경망 쪽 의심 (화면만으로 위치를 모름)
  - ③ 둘 다 −15%p 안쪽 → 줄 외우기 가설 기각. 경로 밖에서도 됨 → 갇힘(기억) 쪽이나 목표 정보로

  - 교란: k=3/6의 도착률이 k=0보다 −20%p 넘게 떨어지면 "벗어나면 못 돌아옴". 오차 안이면 회복은 됨 (단 밀린 거리 3~5칸 범위에서만)

- **결과** (10-07. `train.offpath eval` 칸 8 × 4판 + 짝, `perturb` 조건당 25판. 세 모델 같은 실행)

### GOAL1 (설계 초안, 시드 1 판정 후 확정): 목표 정보 + 양방향 29번도로를 정책 하나로
- **왜**: 스토리 다음 구간이 왕복 (무궁시티 ↔ 연두마을을 두 번 지남). 같은 29번도로 화면에서 정답 방향이 반대 → 화면만 보는 정책은 한 방향밖에 못 함. 여러 구간을 정책 하나로 하려면(T1에서 순차 학습은 잊음) 섞어 학습 + 목표 정보가 필요
- **준비 완료 (10-07, 학습 없이)**
  - 구간 `route29_rev`: 29번도로 서쪽 끝 (0,7) → 연두마을. 시작 상태 = route29 시연 마지막 칸 상태 (HP 같음)
  - 거리표: 491칸 탐색, 476칸, **최단 70걸음** (정방향 103: 턱을 동쪽으로는 뛰어내려 지름길로 씀 → 같은 도로라도 길이 다름)
  - 시연 72칸 (HP 17~19), 경로 밖 상태 395칸 (전투 중 상태 0, HP 17~19)
  - 녹화 버그 수정: (41,10)은 걸음 뒤 60프레임이 지나서야 인카운터가 시작돼서 "피했다"고 저장한 상태가 실제로는 전투 중이었음 → 기다리는 시간 120프레임 + 타이밍 후보 16가지. 기존 데이터(route29/newbark 시연, route29 경로 밖)는 검사해서 전투 중 상태 0 확인
- **설계 (안)**
  - 관찰: 화면 + 목표 맵 원핫 (구간의 goal_maps. 무궁시티 / 연두마을). 좌표나 방향은 안 줌 (그건 거리 보상 같은 선생님 신호가 됨). `--memory`와 같은 Dict 관찰 방식
  - 학습: 정책 하나, 환경 6개를 정방향 3 + 반대 방향 3. 구간마다 자기 시연 전선/폭 커리큘럼 (`route29_demo_lat` 규칙 그대로). 보상 `goal_only`, tile
  - 대조군: 같은 섞어 학습에서 목표 정보만 뺀 것 → 한쪽 방향으로 쏠리거나 둘 다 어중간할 것으로 예상. 목표 정보가 차이를 만든다는 직접 증거
- **판정 (안)**: 양방향 각각 경로 위 ≥ 80% (정방향은 LAT1 96~100%, 반대 방향 기준선은 따로 학습한 구간 전용 모델). 대조군은 한 방향 이상 < 50%
- **구현 (10-07)**
  - `GoldEnv(obs_goal=True)`: 관찰 Dict에 `goal` 96칸 = 목표 맵 그룹 원핫 32 + 번호 원핫 64 (구간의 goal_maps 첫 번째). 크기 고정 → 구간이 늘어도 신경망 입력 그대로. 확인: route29 (26,3) → 칸 26, 35 / route29_rev (24,4) → 칸 24, 36
  - `--goal` (env_config.json에 `obs_goal` 저장 → 진단/경로 밖/라이브/시청이 자동으로 따름). 정책은 MultiInputPolicy, 신경망 모양은 CnnPolicy와 같게 (MEM과 같은 방식) → 바뀌는 건 입력 96개뿐
  - `--env route29_bidir_lat`: 환경 i가 `parts[i % 2]` 구간을 맡음 (6개 → 정방향 3, 반대 3). 구간마다 LAT1 규칙(시연 전선 + 경로 옆 시작 25% + 폭)
  - `MultiDemoCurriculumCallback`: 구간별 전선/폭. TensorBoard `game/demo_front/<구간>`, `game/real_goal/<구간>`, `game/lat_*/<구간>`. 저장 `demo_ptr.json` = {구간: {ptr, radius}}

  - 시험: 환경 2개 2천 스텝 학습 → 구간별 기록 생김, 진단에서 관찰 모양 맞음 (시험 결과물은 지움)
