## 1. 일관성 시험 (10-23) — `train/consistency_check.py`
- 세 경로를 **실제 코드 그대로** 돌림: 학습(`MultiSegmentEnv` 실제 시작 = SB3가 받는 reset/step 관찰), 단독 평가(`diagnose.run_one`), 통합 실행(`run_story.main`). 코드 동작은 안 바꾸고, PyBoy 대리 객체(진행·그리기 프레임 기록)와 기록용 정책만 끼움
- 학습 경로에서 M2B가 고른 행동열을 저장 → diagnose·run_story에 같은 행동열을 넣고 예측마다 위치·예측 사이 프레임·관찰 해시·목표 칸·시간대 RAM·지난 화면 프레임을 비교
- 범위: 4구간 (newbark_labdoor = E-lab, route29 풀숲, route30 트레이너, cherrygrove_pc 건물) × 시계 lock·day·night × 시드 2 (diagnose 시작 흘림이 0인 시드 27·108) = 24사례. 결과 `runs/consistency/1023_092130.json` (걸음 기록 포함 재현: `1023_092624.json`)
- 재실행: `uv run python -m train.consistency_check` (약 15분). 기록 대조만: `--records-only`

### 발견 (의도하지 않은 차이 → 사용자 결정 필요)
- **C1. 통합 실행의 '지난 화면' 오판 (+1프레임)**: 막힌 걸음 뒤 run_story가 `can_move`(눌러보고 되돌리기)를 부르면 PyBoy `frame_count`가 올라감 (되돌려도 안 줄어듦). → `--fresh-obs`가 지난 화면으로 판단하고 1프레임 더 그림 → 게임 시간이 학습보다 1프레임 밀려 이후 조우 난수가 갈라짐. 실제 화면은 바뀌지 않았음 (대리 객체 기준 지난 화면 0)
  - 부수 영향: run_story가 기록하는 `stale_obs` 수(10-20 '판당 약 550번')에는 이 오판이 섞여 있음. 진짜 지난 화면(매크로·전투 뒤)은 있었으므로 10-20 수정과 그 뒤 재측정의 결론은 그대로지만, 숫자는 과대
- **C2. 잠김·늦은 조우 판별 시점이 다름**: 학습·평가는 걸음 직후 `SCRIPT_LOCK != 0`이거나 이미 전투일 때만 매크로. 통합 실행은 막힌 걸음마다 `can_move`로 약 56프레임 앞까지 시험해 보고 못 움직이면 바로 `run_event`
  - 결과: 트레이너가 다가오는 중·조우 전환 중인 화면을 학습 정책은 1걸음 이상 보고 행동하지만, 통합 실행에선 그 화면이 정책에 안 감 (route29 시드 108 #25, route30 시드 27 #40 — 같은 막힌 걸음에서 통합 실행만 2,297·2,537프레임 매크로)
  - 학습한 관찰 분포와 실전 분포가 다른 지점. 어느 쪽에 맞출지가 결정 사항
- **C3. run_story 숨은 버그**: 목표 목록의 마지막이 할아버지 집(26,10)이면 이벤트 처리 뒤 `targets[ti]` 범위 초과로 멈춤 (`run_story.py:157`, 시험 route30 5사례). 실제 실행은 늘 연구소가 마지막이라 걸린 적 없음
- **C4. 첫 관찰 = 세이브 상태의 팔레트 (세 경로 공통)**: reset이 1프레임만 그림. 시간대 조건이 세이브와 다르면 첫 관찰이 다른 시간대 색. 상태마다 바뀌는 데 1프레임(E-lab·route29) 또는 약 5프레임(route30·cherrygrove_pc 시작 상태)이 걸림 → `POKE_FRESH_FIRST=1`(1프레임)은 E-lab에선 충분하지만 일부 상태엔 부족. lock에서도 route30·cherrygrove_pc 시작 상태는 저장된 시간대 RAM이 낮(1)이라 첫 관찰만 낮 색이고 그 뒤 아침
  - 학습(lock)에선 판마다 첫 1걸음만 해당. E26 16구간 낮·밤 평가에서는 첫 걸음이 다른 시간대 색

### 의도된 차이 (시험에서 제외, 기록만)
- **D1 종료 범위**: 통합 실행은 구간 밖으로 나가도 판이 안 끝나고 계획기가 이어감 (학습·평가는 이탈 = 실패 종료)
- **D2 회복 규칙**: 통합 실행은 새 마을 첫 도착이면 목표 도착 판정보다 회복이 먼저 (route29 → 무궁시티 도착 걸음에서 학습은 성공 종료, 통합 실행은 센터로 감)
- **D3 걸음 상한**: 학습·평가 = 구간 max_steps, 통합 실행 = `--max-steps` (판 전체)
- **D4 diagnose 시작 흘림**: 판 시작 뒤 0~29프레임 안 그리고 흘림 (조우 타이밍 다양화). 첫 관찰이 그만큼 지난 화면 (그동안 화면 변화가 없으면 영향 없음). 시험은 흘림 0 시드로 맞춤
- **D5 학습 전용 무작위화**: 시연 전선·경로 옆 시작·구간 뽑기·추가 시작 상태 (평가·통합 실행엔 없음)
- **D6 평가 전용 기록**: 감지기 관찰, 반사실 덮어쓰기(`POKE_OVERRIDE_*`), 판당 시간 상한

### 정리 목록에 올릴 것 (동작 영향 없음)
- `GoldEnv._settle_battle`: 정의만 있고 부르는 곳 없음
- 시계: `lock` = 상태마다 저장된 시각 그대로 (지금 시험 4개 상태는 모두 아침으로 수렴). 문서에 '고정 = 아침'이 아니라 '상태별 저장 시각'으로 적어야 함

### 수정 (10-23 사용자 결정: C1·C3·C4 고침, C2는 통합 실행을 학습 쪽에 맞춤)
- **C4** `envs/gold_env.py`: reset 뒤 `RESET_FRAMES = 4` (3프레임 안 그리고 + 1프레임 그림)를 첫 관찰로. 구간 상태 19개 × 시계 lock·morning·day·night에서 밝기·시간대 RAM이 안정되는 데 최대 3프레임 (측정)
- **C1** `envs/heal.py`·`envs/menu.py`: 눌러보고 되돌리는 시험 프레임을 `PROBE_FRAMES`로 셈, `real_frames(pb)` = 실제 진행 프레임. `run_story` 지난 화면 판별이 이걸 씀
- **C2** `train/run_story.py`: 환경에 모델의 `auto_event`를 넘기고, 자체 '막히면 can_move → run_event'와 '걸음 뒤 늦은 전투' 처리를 뺌 → 학습과 같은 시점 (걸음 직후 SCRIPT_LOCK / 전투 중). `late_battles`는 이제 늘 0
- **C3** `train/run_story.py`: 할아버지 집이 마지막 목표면 이벤트 뒤 성공으로 끝냄
