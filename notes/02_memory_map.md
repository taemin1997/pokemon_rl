# 02. 한국어판 금 버전 메모리 주소 검증

## 배경
- ROM: 한국어판 금 (`POKEMON_GLD` / `AAUK`, CGB 전용)
- 참고 자료인 pret/pokegold 심볼은 영문판 기준
- 영문 주소로 읽으면 쓰레기 값이 나옴 (예: 맵 `247:247`, 파티 `247마리`, 배지 `11111111`)

## 원인
한국어판은 이름 같은 문자열이 한 글자에 2바이트임(ID 바로 뒤 이름 버퍼에서 `0B 00`이 반복되는 걸 확인함).
문자열 버퍼가 길어지면서 그 뒤에 있는 변수들이 통째로 뒤로 밀림. 밀린 양은 구간마다 다름.

## 찾은 방법
1. 화면에 보이는 값을 메모리에서 바이트 패턴으로 검색함
   - 트레이너 카드의 소지금 3000원 → `00 0B B8` (3바이트 빅엔디언 이진수)
   - 처음에는 1세대처럼 BCD(`00 30 00`)로 검색했는데 아무것도 안 나옴. 2세대는 이진수로 저장함
   - ID 25572 → `63 E4`
2. 캐릭터를 한 칸씩 움직이면서 같이 1씩 바뀌는 칸을 찾음(좌표). 영문판 배치(그룹, 번호, Y, X 순서)를 그대로 대입해 봄
3. `step2_pyboy/01_read_memory.py`로 직접 플레이하면서 화면 값과 대조함
4. WRAM 0xD000~0xDFFF는 뱅크 전환 구간이라 항상 `memory[1, addr]`(1번 뱅크)로 읽음

### 전투 메뉴 찾기 (10-07, 전투 모듈 B1용)
1. 29번도로 풀숲을 무작위로 걸어 야생 전투 시작 상태를 저장 → A를 눌러가며 문구를 넘기고 메인 메뉴(싸우다/가방/포켓몬/도망치다)를 화면으로 확인
2. 메인 메뉴에서 오른쪽 → 아래 → 왼쪽 → 위로 커서를 한 바퀴 돌리며 WRAM(C000~DFFF)을 매번 저장 → "행처럼 바뀌는 바이트", "열처럼 바뀌는 바이트"를 거름 → **CEB5(행), CEB6(열)** 하나씩만 남음 (1부터 셈)
3. 싸우다 → 기술 목록에서 아래/위 → 같은 CEB5가 기술 칸 번호. 그래서 전투 전용이 아니라 게임 공통 메뉴 커서로 봄
4. 그 앞쪽 바이트(CEAD~CEB0)가 메뉴가 열릴 때마다 새로 써짐: 메인 메뉴 (14, 9, 2행, 2열), 기술 목록 (10, 1, 기술 수, 1열) → "지금 어떤 메뉴가 열려 있나" 판별에 씀 (`battle_menu()`)
5. **반대 상황 확인** (전투 플래그 실수 교훈): 전투 2개 × 3턴, 매 A마다 판별 결과와 화면을 대조 → 메뉴 화면은 전부 맞고, 문구 화면에서 메뉴로 잘못 판별한 경우 0. 메뉴가 닫혀도 블록 값이 남지만 커서가 0이 돼서 걸러짐
- 덤: CAEF~ 에 지금 커서가 올라간 기술의 번호/효과/위력/…/PP (할퀴기 10, 0, 40 … 35)
- 미확인: 기술 3~4개일 때 기술 목록 시작 줄, 트레이너 전투, 가방/포켓몬 메뉴 안

### 전투 플래그를 찾다가 한 실수 (기록용)
1. 29번도로 풀숲을 무작위로 돌아다니다가 야생 전투가 터지게 만듦. WRAM 전체를 매 스텝 기록한 다음,
   "전투 전엔 0, 전투 동안 계속 1, 끝나면 0"인 바이트를 골라냄
2. 처음엔 후보 중 D21B를 골랐음. 그런데 학습된 모델을 돌려보니 집 안에서 "전투"가 수십 번 찍힘
3. 그 순간들을 스크린샷으로 보니 전부 **대화창** 장면이었음. 전투도 대화창(전투 메시지)이 계속 떠 있으니까
   "대화창이 떠 있다" 플래그가 전투 조건까지 같이 만족해버린 거임
4. 조건을 하나 추가함: "전투 동안 켜짐" + "**대화창 장면에서는 꺼짐**". 이렇게 다시 거르니 D1D3이 남음
5. D1D3은 영문판 D116 + 0xBD. 같은 밀림을 적 종(D1AC = 19 꼬렛), 레벨(D1B9 = 4)에도 적용하니 화면과 일치해서 확정함

교훈: 후보를 고를 때는 **"켜져야 할 때 켜지는지"뿐만 아니라 "꺼져야 할 때 꺼지는지"도 반대 상황에서 확인해야 함**

- 맵 번호와 종 번호 값 자체는 영문판과 같음. 위치만 밀려 있음
- 배지 0번 비트 = 도라지 체육관(윙배지) = 프로젝트 최종 목표
