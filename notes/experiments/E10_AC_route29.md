# AC_route29 (역방향 커리큘럼 v3: Go-Explore식 아카이브)

> 실험 기록 (가설, 판정 기준, 결과, 해석). 공통 조건은 `notes/04_experiments.md`

- **바꾼 것**: 후보를 만드는 방식만 (보상 `goal_only`, PPO 그대로, 거리표 안 씀)
  - 모든 판에서 에이전트가 처음 밟은 좌표를 5걸음마다 아카이브에 저장 (좌표당 하나, 최대 300)
  - 시작 고르기: 10% 실제 입구, 나머지는 아카이브에서 가중치로 (성공률 20~80% 또는 덜 해본 곳 1.0, 너무 쉽거나 어려운 곳 0.1) ÷ √(뽑힌 수+1)
  - 씨앗 6개 (목표 1~4걸음)
- **구현 확인**: 무작위 행동 40판만으로 아카이브 181개, 목표까지 거리(분석용) 1~104, 중앙 22 → **경로 전체를 빠르게 덮음** (RC2는 10만 스텝 후에도 5걸음 안쪽)
- **가설**: 후보가 경로 전체에 고르게 있으면, 목표 근처부터 성공 → 성공률 밴드가 "적당히 어려운 곳"을 골라주면서 실력이 입구 쪽으로 퍼짐
- **판정 기준** (250k, `train.diagnose route29`): S1 도착 ≥ 30% → 분기점 통과 / 도착 낮지만 `real_goal`이나 진행이 오름 → 연장 / 진행이 A3 수준(약 47) → 재설계
- **볼 지표**: `real_goal`, `rc_pool`(아카이브 크기), `start_dist`(아카이브에서 뽑힌 시작 위치. 전선이 아니라 연습 분포)
- **결과**: ❌ 77k에서 중단 (커리큘럼이 너무 어려워짐)
  - 아카이브 11 → 122(30k) → 170(77k). 연습 판 도착률 67% → 22% → **14%**, 판 길이 155 → 401 (대부분 시간 초과)
  - 엔트로피 -1.78 → -1.63 (거의 안 굳음). 라이브에서 빙글빙글 도는 모습. 실제 입구 도착 0%
  - 원인: 모든 판의 자리를 다 넣어서 아카이브가 먼 자리로 금방 가득 참 + 새 자리는 "덜 해봄" 우선순위 1.0 → 거의 매번 너무 어려운 곳에서 시작 → 보상이 드물어져서 학습 신호 부족
  - RC2가 "너무 느리게 넓어짐"이었다면 AC는 **"너무 빨리 넓어짐"**
  - 참고: `start_dist`가 200처럼 튄 건 거리표에 없는 자리를 999로 기록한 탓 → AC2부터 제외
