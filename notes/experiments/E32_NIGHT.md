# E32 NIGHT — 밤 성공률이 낮은 원인 진단 (학습 없음, 평가만)

> 트랙 [B]. 2026-10-23 **설계 초안** — 판단 기준은 제안값, 사용자 확정 전엔 측정 안 함. 10-22 합의 순서 ② (아키텍처 점검 ① 뒤, E31 전)
> 코드: 10-23 일관성 수정 뒤 (C1~C4, `notes/architecture.md`). 옛 밤 숫자와 판 단위로 섞지 않음

## 질문
- 통합 실행에서 다섯 모델 모두 밤이 가장 나쁨 (E26 판정 3: 밤 0~9/20, 아침 12~17). **원인이 시각 정보(밤 색)인가, 게임 동작(밤 조우·NPC·이벤트)인가, 실행기·비계인가**
- 10-22 사용자: 시간 무작위화부터 넣지 말고, 같은 체크포인트·같은 출발에서 게임 시간만 바꿔 비교 + 관찰·행동이 처음 갈라지는 지점 기록 → 결과 보고 무작위화 여부 결정

## 이미 있는 근거 (옛 코드, 참고만)
- 밤 실패 원인이 모델마다 다름: A_s0 = 건물 진입 후 계획 없음 10판 (비계), A_s1 = 31·30번도로 정책 18판, B_s1 = 29번도로 풀숲 맴돌기, M2B = 연구소 문 앞 P(위 = 재진입) 아침 0.58 / 낮 0.74 / 밤 0.90
- 구간 단독 평가에서도 밤에 떨어지는 곳이 있음: M2B route30_north·route31 밤 3/25, route30 아침 96 / 밤 84%
- **학습 때 본 시간대가 모델마다 다름**: M2A·M2B 계열은 실제 시계(wall)로 학습 → 학습한 시각에 따라 밤 비중이 다름 (확인 안 됨). E26·E30 계열은 lock (상태별 저장 시각, 시험 상태는 모두 아침으로 수렴)

## 장치: 같은 게임 상태를 다른 시간대 색으로 그리기 (10-23 확인)
- 상태 저장 → 시작 시각(D298)만 아침/밤으로 바꿈 → 4프레임 진행 후 그림 → 원래 상태로 되돌림. 게임 진행에는 영향 없음
- 확인 (route29·newbark_labdoor·route31, 10걸음): 밤 게임을 아침 색으로 그린 화면 = 같은 칸 아침 게임 화면 (route29·route31 100% 같음, 연구소 문 앞은 꽃·물 애니메이션으로 평균 밝기 차 0.3 vs 그냥 밤 화면 차 44.7)
- → **게임 = 밤, 눈 = 아침** 같은 조건을 만들 수 있음 (E29 반사실과 같은 방식: 판정 대상만 바꾸고 나머지 고정)

## 설계
### 1단계: 밤 약점 구간 찾기 (구간 단독 평가)
- 모델: **M2B** (트랙 B 기준선, wall 학습) / **E30_D_s0·E30_D_s1** (최신, lock 학습). 모델별 따로 판정
- 구간: 기존 16구간 + E-lab (`newbark_labdoor`) + E-violet (`violet_pc_counter`, 평가 전용)
- 시계: 아침·낮·밤 (`POKE_CLOCK=morning|day|night`), 각 50판, 같은 시드 0~49
- **밤 약점 구간**: 밤 길 찾기 실패 − 아침 실패 ≥ +10%p (50판 ±2표준오차 ≈ ±14%p라 +10~+20%p는 '경계'로 표시)

### 2단계: 2×2 분해 (약점 구간만)
| 조건 | 게임 시간 | 정책이 보는 색 |
|---|---|---|
| MM | 아침 | 아침 (1단계 값 재사용) |
| NN | 밤 | 밤 (1단계 값 재사용) |
| **NM** | 밤 | 아침 (다시 그린 화면) |
| **MN** | 아침 | 밤 (다시 그린 화면) |
- 같은 시드 0~49. 시각 효과 = NN − NM (밤 게임에서 눈만 바꿈), 게임 동작 효과 = NM − MM (눈은 아침으로 같고 게임만 다름). MN은 반대 방향 확인용
- 다시 그리기는 걸음마다 (판당 수백 번 상태 저장·불러오기 → 평가 시간 약 2배 예상)

### 3단계: 처음 갈라지는 지점 (짝지은 판)
- 같은 시드의 MM 판과 NN 판을 걸음마다 기록: 위치, 행동, 정책 행동 확률, 전투·잠김 여부
- **처음 갈라지는 걸음**을 종류로 나눔: (a) 위치·전투가 같은데 행동이 다름 = 정책이 색에 반응 / (b) 행동이 같은데 조우·NPC·잠김이 다름 = 게임 동작 / (c) 실행기·규칙 (통합 실행만)
- 같은 칸에서 아침 색 vs 밤 색 정책 분포 차이 KL (판정엔 안 쓰고 보고, E29 길목 칸 KL과 같은 방식)

### 4단계: 통합 실행 밤 (고친 실행기)
- 위 세 모델, 아침·밤 각 20판 (`run_story`, 고친 코드). 실패를 rule / transition(계획 없음) / policy / 전멸로 분류 → 구간 결과와 이어서 해석
- 통합 실행 2×2는 이번엔 안 함 (구간에서 원인이 나오면 E33에서)

## 판단 기준 (제안, 확정 필요)
- 약점 구간마다 밤 실패 증가분 Δ = NN − MM
  - **시각 주도**: NN − NM ≥ 0.5·Δ (눈만 아침으로 바꿔도 절반 이상 회복)
  - **게임 동작 주도**: NM − MM ≥ 0.5·Δ
  - 둘 다 아님 = **섞임**
- 모델별로 약점 구간 다수가 어느 쪽인지 보고. 다음 실험 연결 (결과 보기 전 고정):
  - 시각 주도 → 학습 시간대 무작위화 (또는 시계 조건별 학습 비중) — E33 후보
  - 게임 동작 주도 → 밤 조우·NPC 경험 (밤 시작 상태·밤 시연) — E33 후보
  - 통합 실행에서 비계 실패(계획 없음·규칙) 비중이 크면 → 비계 수정 먼저 (RL 실험 아님)
- 약점 구간이 없으면 (모든 구간 Δ < +10%p) → 밤 문제는 구간 단독이 아니라 통합 실행 쪽 → 4단계 실패 분류로만 해석
- 확인용 (판정 아님): MM을 다시 그리기 경로로 돌린 판 = 일반 경로 판 (같은 시드) ≥ 95% — 다시 그리기 장치가 결과를 안 바꾸는지

## 예산 (추정)
