# M2A_multi (초안): 집 → 포켓몬할아버지 집 → 공박사 연구소, 구간 8개를 정책 하나로

> 실험 기록 (가설, 판정 기준, 결과, 해석). 공통 조건은 `notes/04_experiments.md`. 경로/이벤트는 `notes/07_m2a_story.md`

- **왜**: GOAL2(E22)가 정책 하나로 29번도로 양방향 (96 / 100%). 스토리 다음 구간(M2a)은 구간 8개 왕복. 구간마다 모델을 두면 T1처럼 잊음/교체 비계가 남음 → 목표 조건 정책 하나로
- **바꾼 것 (GOAL2 대비)**: 구간 2개 → 8개 (`--env m2a_multi`, `MultiSegmentEnv`). 환경이 구간을 고정으로 맡는 대신 **판마다 구간을 뽑음** (균등). 콜백 `MultiSegCurriculumCallback` (구간별 전선/폭, 규칙은 같음). 나머지 GOAL2와 같음 (`--goal --hidden 256,256`, goal_only, tile, 수정 코드)
  - 구간 11개: + **cherrygrove_pc**(무궁시티 → 센터, 14), **cherrygrove_pc_exit**(센터 → 무궁시티, 5) (회복 규칙, 10-08 사용자 제안)
  - 구간 9개 (위 둘 추가 전): **house2f**(전멸 부활 위치 → 집 1층, 7), newbark, route29, cherrygrove, route30, route30_rev, cherrygrove_rev, route29_rev, newbark_lab (최단 7 / 24 / 103 / 30 / 60 / 59 / 30 / 70 / 12)
  - **전멸 대응**: 전멸하면 집 2층(HP 가득, 돈 절반)에서 다시 시작 → `envs/planner.py`가 맵 연결 그래프(구간 edges에서 자동)로 "지금 맵 → 최종 목표" 맵 순서를 계산 → 정책에 다음 목표 맵을 줌. 한 판 평가에서 전멸해도 끝내지 않고 이어가는 방식으로
  - 비계: 시연(BFS), 경로 밖 상태(없는 구간은 시연만), 이벤트 4개는 구간 경계에서 처리(A 매크로/이벤트 뒤 상태), 상위 계획(구간 순서)은 사람
  - 주의: 구간마다 받는 경험이 1/8 → 예산 크게 필요. GOAL2(구간당 1/2)가 50만에 양방향 입구 도달
- **가설**: GOAL2의 목표 조건 정책이 구간 8개로 늘어도 같은 방식으로 학습됨 (목표 맵이 다 다름: 29번도로, 무궁시티, 30번도로, 할아버지 집, 연두마을, 연구소)
- **판정 기준 (초안, 학습 전 확정)**: 구간별 실제 출발 도착 ≥ 80% (`train.diagnose <구간>`), 한 판 전체(집 → 할아버지 집 → 연구소, 이벤트는 비계) 성공률
- **예산 (안)**: 150만~200만 (초당 약 70스텝 → 6~8시간). 중간 체크포인트마다 구간별 진단
- **미해결 전에 정할 것**: 연구소 이벤트 ④(이름 입력)는 메뉴 트랙 전까지 "연구소 문 도착"을 목표로. 한 판 전체 시험 스크립트 (watch_roundtrip 확장)
- **결과**: (학습 후 기록)

## 확정 (10-09 16:0x, 학습 전) — 사용자: "컴퓨터 오래 켜둘 테니 오래 걸리는 것도 알아서"
- 명령: `uv run python -m train.train_ppo --env m2a_multi --init models/GOAL2_route29/final.zip --reward goal_only --move tile --goal --hidden 256,256 --fast-battle --steps 2000000 --name M2A_multi --no-live`
- 초안에서 바꾼 것 (트랙 B = 진행 우선, 결과 보기 전 결정)
  - **--init GOAL2**: 29번도로 양방향은 이미 배운 상태에서 시작. 근거: E25에서 GOAL2 초기로 새 구간이 ≤ 10만 스텝에 학습됨 (NM3 결과로 전이 여부 확인 예정). T1의 부정적 전이는 "한 구간 → 다른 한 구간 순차"였고 여기선 섞어 학습이라 잊음 위험 낮음
  - **--fast-battle**: 전투 결과가 같음을 확인한 옵션 (progress/battle.md). 200만 스텝이라 속도 우선. 트랙 A 비교군들과는 비교 안 함
  - 시드 0, 스모크 시험 (2,048스텝, 환경 2개) 통과
- **판정 (주)**: final로 11개 구간 각각 `train.diagnose <구간>` 25판 → **모든 구간 실제 출발 ≥ 80%**. 보고는 구간 평균 + **최악 구간**
- 참고 (판정 안 씀): 경로 밖 (offpath.pkl 있는 구간), 한 판 전체 시험 (스크립트 아직 없음 → 다음 단계)
- 실패 시 원인 구분: 특정 구간만 낮음 (전선이 입구 못 감 → 예산/가중치) vs 전반 낮음 (구간 수가 많아 목표 구분 실패 → 목표 표현)

## 판정 기준 수정 (10-09 23:2x, 학습 중 — 구간별 최종 평가 보기 전, 사용자 제안)
- **주 판정: 구간마다 "길 찾기 실패율" (시간초과 + 구역 이탈, 전멸 판 제외) ≤ 20%** — 11개 구간 전부
- 같이 보고 (판정 안 씀): 전체 도착률 (전멸 포함), 전멸률. 보고는 구간 평균 + 최악 구간
- 이유: 이 정책이 배우는 건 길 찾기. 전투는 A 연타 자동, 전멸은 전투 누적 + 구간 시작 HP(시작 상태마다 다름)에 좌우 → 길 찾기 점수에 섞으면 원인을 잘못 탓함. 실제 플레이에서도 전멸은 부활 위치에서 이어감 (원칙: 전멸은 지표로만)
- 전멸을 아예 빼지 않는 이유: 풀숲을 헤매는 정책은 전투·전멸이 늘어남 → 전멸률을 같이 봐야 비효율이 가려지지 않음
- 전멸 대응은 길 찾기 정책이 아니라 트랙 B 회복 규칙 + 부활 뒤 복귀 → 통합 실행(한 판 전체)에서 판정
- 바꾸기 전 기준 (11개 구간 전체 도착률 ≥ 80%)도 결과표에 같이 적음 (기준 바꾼 효과가 보이게)

- 옛 기준 (전체 도착 ≥ 80%)으로도 route30 실패
- **원인 (잠정)**: route30 출발 칸 = 무궁시티 경계 = route30_rev의 마지막 칸 (그 칸에서 남쪽으로 한 걸음이 route30_rev의 정답). 같은 화면에서 목표(할아버지 집 26,10 vs 무궁시티 26,3)를 무시하고 습관대로 남쪽 → 분기점 목표 구분 실패 (GOAL2의 "목표 바꿔치기" 약점과 같은 종류). 학습 중 전선 성공률도 route30만 0.75였음
- 전멸 4판은 집 2층에서 끝남 (그중 2판은 whiteout 표시가 안 됨 → **전멸 감지 누락 확인 필요**)
- 걸음: 대부분 최단 +0~3. route29_rev(90 vs 70), route30_rev(75 vs 59)는 돌아감 (이동 80 / 70)
- 해석: 정책 하나로 목표 11개 중 10개 완벽. 실패는 "길을 모름"이 아니라 **두 목표가 같은 칸에서 반대 방향을 요구하는 분기점** 하나. 통합 실행에선 되돌아가도 상위 계획이 다시 목표를 주면 다시 들어감 (손해는 걸음 수) → 진행 차단은 아님
- 다음 후보 (하나씩): ① route30 가중치 올려 이어 학습 (MultiSegmentEnv weights) ② 짧은 기억(--memory, "어디서 왔나" — LAT1_MEM에서 확인된 역할) ③ 통합 실행에서 실제로 문제 되는지 먼저 확인
