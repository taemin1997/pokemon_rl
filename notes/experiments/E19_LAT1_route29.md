# LAT1_route29 (DEMO_TILE + 경로 옆 시작: 진행도 × 폭 2차원 커리큘럼)

> 실험 기록 (가설, 판정 기준, 결과, 해석). 공통 조건은 `notes/04_experiments.md`

- **바꾼 것**: 판 시작 자리만 (`--env route29_demo_lat`, `LateralDemoEnv`). 보상 `goal_only`, `--move tile`, PPO, 전선 당기기 규칙, 시드 0 모두 DEMO_TILE과 같음
  - 판 시작: 실제 입구 10% / **경로 밖 칸 25%** / 시연 전선 65% (DEMO_TILE은 입구 10% / 전선 90%)
  - 경로 밖 후보: `offpath.pkl`의 경로 밖 칸 중, 가장 가까운 시연 칸이 전선 뒤쪽(이미 익힌 쪽)이고 경로에서 1~radius걸음. 절반은 가장 바깥(= radius), 절반은 안쪽
  - radius: 1에서 시작. 가장 바깥 칸에서 시작한 판이 24판 이상 + 도착 ≥ 50%면 +1 (최대 8). 전선과 같은 원리
  - 비계 추가: 경로 밖 시작 상태 (BFS로 걸어가서 만든 세이브, 전투 피한 타이밍 → HP 시연과 같음). 버튼은 여전히 안 줌
- **평가 칸 분리 (학습에서 뺌)**
  - 지역 단위: 중간 남쪽 주머니 (24,3) x 15~27, y 10~15의 경로 밖 칸 58개 전부 (`envs/offpath_tiles.py` HOLDOUT_REGIONS). 경로 위 칸(시연)은 그대로 씀
  - 칸 단위: OFFPATH1 진단 칸 32개 + 바로 옆 칸 (빼둔 지역과 겹치는 것 포함 102칸)
  - 학습에 쓰는 경로 밖 칸 259개 (경로에서 1~8걸음. 10+는 전부 빼둔 지역이라 학습엔 없음)
  - 진단 칸 32개 중 14개가 빼둔 지역, 18개가 나머지
- **기준선 (OFFPATH1을 지역으로 나눔, 경로 밖 시작 도착률)**

| 정책 | 빼둔 지역 (14칸) | 나머지 (18칸) |
|---|---|---|
| DEMO_TILE 시드0 | 0% | 92% |
| DEMO_TILE 시드1 | 52% | 89% |
| B2 | 0% | 85% |

  - 실패가 거의 다 빼둔 지역에 몰려 있음. 나머지는 이미 85~92%라 여유가 적음 (안 되는 건 서쪽 아래 (5,12), (15,12), (16,10), (20,11))
  - 시드끼리 차이가 큼 (0% vs 52%) → 판정 문턱을 두 시드 중 높은 쪽 기준으로 잡음
- **가설**: OFFPATH1의 경로 밖 실패가 "학습 분포가 좁아서"라면, 경로 밖에서도 시작해 본 정책은 한 번도 시작 안 한 지역(빼둔 지역)에서도 길을 찾음
- **판정 기준** (결과 보기 전에 정함. `train.offpath eval route29` LAT1 + DEMO_TILE 두 시드 같은 실행, `perturb`도 같이)
  - 빼둔 지역 ≥ 67% (기준선 최고 52% + 15%p) → **분포 문제였고, 안 가본 지역으로 번짐**. 경로 옆 시작을 이후 기본 커리큘럼으로
  - 빼둔 지역은 그대로(< 30%)인데 나머지의 서쪽 아래 4칸이 오름 → 분포 문제지만 "가본 곳 근처"까지만 번짐 → 다음은 관찰 쪽 (가본 칸 지도, 목표 정보)
  - 둘 다 그대로 → 분포 문제 아님 → 관찰/표현 문제
  - 30~67% → 애매. 시드 1 하나 더
  - **안전 조건**: 경로 위 진단(`train.diagnose route29`) start/S2/S3 ≥ 80% 유지 (M1이 안 깨짐). 깨지면 경로 밖 판 비율이 시연 연습을 갉아먹은 것
- **예산**: 300k (DEMO_TILE 250k). 시연 판 비율이 90 → 65%라 전선이 약 1.4배 느려질 것 (DEMO_TILE은 18.7만에 입구) → 250k면 입구에 못 닿을 수 있음. 판정은 300k `final.zip`, 참고로 250k 체크포인트도 같이 진단
- **해석 주의**: 전선이 입구에 늦게 닿으면 입구 근처 굳히기가 짧아짐 → 경로 위 도착률 차이가 경로 옆 시작 탓인지 굳히기 시간 탓인지 섞일 수 있음
- **결과** (10-07. 30만 `final.zip` + 25만 체크포인트. DEMO_TILE 두 시드와 같은 실행)
  - 학습: 전선 입구 도달 20.9만 (DEMO_TILE 18.7만), 폭 8(최대) 16.9만. 학습 중 입구 판 22만 이후 100%, 경로 밖 판 86~100%. 판당 전투 약 2.8 (DEMO_TILE 3.4), 초당 48스텝 (같음)
  - 경로 위 (안전 조건, `train.diagnose route29`)

| 정책 | start | S2 | S3 | 도착 걸음 (start) |
|---|---|---|---|---|
| LAT1 30만 | 96% | 100% | 100% | 110 |
| LAT1 25만 | 96% | 96% | 96% | 124 |
| DEMO_TILE (같은 실행) | 92% | 96% | 100% | 125 |

  - 경로 밖 (`train.offpath eval`, 칸 8 × 4판, 밖 / 짝)

| 경로 거리 | LAT1 30만 | LAT1 25만 | DEMO_TILE 시드0 | 시드1 |
|---|---|---|---|---|
| 1~2 | 97 / 97% | 97 / 100% | 94 / 100% | 97 / 97% |
| 3~5 | 88 / 97% | 88 / 97% | 62 / 97% | 81 / 91% |
| 6~9 | 84 / 97% | 94 / 100% | 34 / 100% | 66 / 97% |
| 10+ | 84 / 100% | 84 / 100% | 12 / 100% | 59 / 100% |
| **빼둔 지역 (14칸)** | **79%** | **82%** | 2% | 55% |
| 나머지 (18칸) | 96% | 97% | 89% | 92% |

  - DEMO_TILE은 OFFPATH1 (0% / 52%)과 거의 같게 재현됨 → 진단 자체는 안정적
  - 교란 복구: LAT1 k=0 96%, k=3/6 88~100% / DEMO_TILE k=0 100%, k=3/6 84~100% → 둘 다 회복 (차이 없음, 1~3칸 범위)
- **판정**: 사전 기준 ① 충족 (빼둔 지역 79%, 25만 82% ≥ 67%. 같은 예산 25만에서 DEMO_TILE 2% / 55%). 경로 위 안전 조건 통과 → **경로 밖 실패의 주원인은 학습 분포가 좁은 것이었고, 넓히면 학습 때 시작한 적 없는 지역으로도 번짐**. 경로 옆 시작을 이후 기본 커리큘럼으로
- **빼둔 지역 칸별** (학습 시작 칸까지 걸음 수): 남쪽 주머니 11칸(학습 칸에서 1~6걸음)은 **전부 4/4**. 실패는 서쪽 통로 3칸 (16,10), (15,12), (20,11)만 0/4 (목표까지 19~24걸음으로 가까운 곳)
  - 추적 (16,10 시작): 목표는 서쪽(거리 14→13…)인데 **동쪽 막다른 끝 (20,10)으로 가서 위/오른쪽을 계속 밈** (300걸음 중 211번 그 칸). (20,11) 시작도 같은 곳에서 같은 행동
  - 같은 통로의 서쪽(x ≤ 14)은 학습 칸이라 됨. 빼둔 상자 안쪽(x ≥ 15)부터 반대로 감 → 이 통로 화면이 "동쪽/위가 정답인 다른 곳"(U턴 쪽 주머니)과 비슷해 보이는 것으로 추정 = **관찰 aliasing**. 분포만으론 안 풀리는 잔여 문제의 구체적 사례
  - DEMO_TILE도 이 3칸은 0% → 원래부터 어려운 칸
- **해석**
  - 비계 추가는 하나 (경로 밖 시작 상태, BFS로 걸어가서 만든 세이브). 버튼/보상은 그대로 → 도움을 넓혀서 일반화를 산 것. "더 적은 도움으로 같은 성능"은 아님
  - 시드 1개. DEMO_TILE 시드끼리 빼둔 지역이 2% vs 55%로 갈렸던 걸 생각하면 핵심 결론이라 **시드 1 재현 필요** (원칙: 핵심 결론은 시드 2개)
  - 25만과 30만이 비슷 (82 / 79%) → 남은 5만은 경로 위 굳히기(S2/S3 96 → 100%)에만 쓰임
  - 남은 실패 = 화면만으론 구별 안 되는 장소 → 다음 관찰 실험(목표/위치 정보, 기억)의 시험 칸으로 씀: (16,10), (15,12), (20,11)
- **시드 1 재현** (`LAT1_route29_seed1`, 10-07. 시드 0과 같은 진단 실행)
  - 학습: 전선 입구 도달 25.2만 (시드 0 20.9만). U턴에서 오래 걸림: 전선 58 (11.4~13.2만, 전선 판 도착 11~40%), 64 = x=31 틈 (14.4~16.6만), 73 = 수풀 주머니 (18.7~19.4만, 전멸 32~46% → 벌점 없이 스스로 풀림)

  - 빼둔 지역 칸별: 남쪽 주머니 11칸은 두 시드 모두 거의 전부 도착. **실패는 두 시드 모두 같은 서쪽 통로 3칸** ((16,10) 0/4, (20,11) 0/4, (15,12) 1/4)
- **재현 판정**: 시드 1도 빼둔 지역 80% (25만 84%) ≥ 67%, 경로 위 ≥ 80% → **LAT1 결과 재현**. 두 시드 범위: 빼둔 지역 77~84%, 경로 위 92~100%. 시드 0 첫 진단(79%)과도 오차 안
  - DEMO_TILE은 시드끼리 2% vs 55%로 갈렸는데 LAT1은 77~84%로 모임 → 경로 옆 시작이 시드 운을 줄임
  - 남은 실패 3칸이 두 시드에서 같음 → 우연이 아니라 구조적 (그 통로에서 반대로 감 = aliasing 추정)
  - 벽 고집은 시드 1도 같음 (막힌 직후 같은 버튼 47%) → LAT1이 고치지 못한 별개 문제
- **결정**: 경로 옆 시작(`*_demo_lat` 방식)을 이후 기본 커리큘럼으로. 대표 모델은 사전에 정한 시드 0 유지
