# DEMO_TILE_route29 (DEMO + 조작 방식만 "방향 버튼 1번 = 1칸")

> 실험 기록 (가설, 판정 기준, 결과, 해석). 공통 조건은 `notes/04_experiments.md`

- **바꾼 것**: 조작 방식만 (`--move tile`). 커리큘럼(`route29_demo`), 보상(`goal_only`), PPO 설정은 DEMO와 같음
  - 방향 버튼을 16프레임 누르고 한 걸음 = 40프레임 (기존 8 / 24). A/B는 그대로
  - 기존 방식은 보고 있는 방향과 다른 방향이면 몸만 돌고 안 걸음 → DEMO 전선 판 걸음의 **56%가 제자리 회전**, 실제 이동 17%
- **구현 확인 (학습 없이)**: 시연 상태 103개에서 네 방향을 한 번씩 → 움직이면 항상 정확히 1칸, 안 움직인 건 벽/턱(33)과 NPC(3)뿐. 같은 방향 연속 누르기도 매번 1칸 (2칸은 턱 점프만). 같은 시험에서 이동 성공 tap 314 → tile 1,271
  - 진단/라이브는 모델 폴더의 `env_config.json`을 읽어서 자동으로 같은 조작 방식으로 평가 (예전 모델은 파일이 없어서 tap)
- **가설**: 회전이 걸음을 갉아먹어서 U턴 같은 곳에서 맞는 길을 우연히 찾을 확률이 낮았다면, 1칸 조작에서는 같은 스텝 수로 전선이 더 빨리 멀어지고 실제 입구 도착도 높아질 것
- **비교 대상**: DEMO_route29 250k (같은 진단 실행에서 나란히)
- **판정 기준** (250k, `train.diagnose route29 models/DEMO_route29/final.zip models/DEMO_TILE_route29/final.zip`)
  - S1 도착률이 DEMO보다 +10%p 넘게 높음 (25판 오차 ±10%p 감안) → 조작 방식이 병목 중 하나였음 → 이후 실험은 tile이 기본
  - 도착률은 비슷한데 같은 스텝에서 `demo_front`가 더 멀리 감 / 도착 걸음이 짧음 → 학습 효율만 좋아짐 → 그래도 tile을 기본으로
  - 차이 없음 → 회전은 겉보기 문제였고 병목은 다른 곳 (U턴 판단, 기억) → 다음 후보로
  - 확인용: 전선 판 걸음 분류에서 회전 비율이 56% → 5% 아래로 떨어져야 함 (아니면 구현 문제)
- **해석할 때 조심할 점**
  - 걸음당 게임 시간이 24 → 40프레임이라 **같은 스텝 수에 실제 시간은 약 1.4배 더 걸림**. "결정 횟수가 같을 때" 비교임
  - A/B를 누르는 걸음은 그대로 낭비 가능 (DEMO에서 약 19%). 이번엔 안 건드림
  - 학습 중 전멸이 늘어난 구간(DEMO 16~17만, 전선 판 전멸 36~67%)이 있었음. 1칸 조작은 같은 걸음에 풀숲 칸을 더 많이 밟아서 전멸이 늘 수도 있음 → 지표로만 봄
- 학습 중 관찰 (3.7만): 전선 28 (같은 스텝 DEMO 22). 전선 구간 도착률 89~95%로 아직 너무 쉬운 곳 (당기기 속도 제한: 롤아웃당 최대 3걸음)
  - 걸음 분류 (전선 6판, 798걸음): 이동 46% (DEMO 17%), 방향 바꿨는데 안 움직임 11% (DEMO 56%. tile은 어느 방향이든 한 번에 걸으니 이건 회전이 아니라 새 방향으로 벽에 부딪힌 것), 같은 방향 벽 12%, **A/B 31%** (DEMO 19%) → 이제 A/B가 가장 큰 낭비
- 학습 중 관찰 2 (8.6만, 전선 58 = U턴 구간. 같은 전선에 DEMO는 약 10.7만): 전선 판 6번 중 도착 1, 걸음의 **45%가 막힘**, 한 판 최장 **47번 연속** 같은 벽. 대부분 (22,11) = DEMO가 갇혔던 왼쪽 막다른 주머니. 입구 판은 (14,14~15), (44,10~11)에서 막힘 → 회전은 없어졌지만 **갇힘은 그대로** (사용자 관찰: "딱 봐도 막힌 곳을 계속 뚫으려 함")
- 학습 중 관찰 3 (18.4만): 전선 100 (입구 3걸음 앞). **실제 입구 판 도착이 처음 나옴** (16만, 전선 88부터) → 17.8만 이후 기록 창마다 50~100% (판 수가 적어 흔들림). 도착 걸음 약 130
- **M1 "정립" 기준 (진단 전에 정함)**: 이 모델을 29번도로 → 무궁시티의 거리 보상 없는 대표 모델로 쓰려면
  - 진단(시작 프레임 흔듦, 25판) S1/S2/S3 모두 도착 ≥ 80% (B2 88~96%와 오차 범위 안)
  - 학습 중 한 번도 시작 안 한 S2/S3에서도 비슷 (경로 위 상태 외우기가 아니라는 근거)
  - 시드 하나 더(250k) 돌려서 전선이 입구에 닿고 S1 ≥ 50% → 우연이 아님
  - 미달이면: 전선이 입구에 닿은 상태로 연장해서 굳힌 뒤 다시 진단
- **결과** (250k, `final.zip`. DEMO, B2와 같은 진단 실행, 시작 프레임 흔듦, 위치당 25판)

|---|---|---|---|---|---|---|---|---|

  - 학습 곡선: 전선 70까지 12만 (DEMO 약 18만), 76까지 13.5만 (DEMO는 25만에 76이 끝), **입구(103) 도달 18.7만**. 실제 입구 판 도착은 전선 88(16만)부터 나오기 시작
- **판정**: 사전 기준 첫 번째 (S1 도착 ≥ DEMO + 10%p) → **조작 방식이 병목이었음**. M1 정립 기준 1·2번 통과 (세 곳 모두 ≥ 80%, 학습 중 시작한 적 없는 S2/S3도 92/100%). 3번(시드 재확인) 남음
- **해석**
  - 커리큘럼, 보상, 신경망이 같고 조작만 다른데 0% → 88~100%. 회전이 걸음의 절반 이상을 먹어서, 같은 예산에 전선이 입구까지 못 갔던 것
  - **거리 보상 없이 B2와 같은 수준** (오차 범위 안). 선생님 역할: B2는 매 걸음 방향 신호, DEMO_TILE은 연습 시작점만 (시연 경로 1개, BFS)
  - S2(44,8), S3(53,9)는 학습 중 시작한 적 없는 자리 → 경로 위 상태만 외운 건 아님. 다만 두 곳 다 경로 근처라, "다른 길"에서의 일반화는 아직 모름 (30번도로 시험)
  - 실패는 전부 전멸 (이탈 = 전멸). 길을 잃어 시간 초과된 판은 없음
  - 도착 걸음이 B2보다 짧지만(123 vs 148) B2는 tap이라 회전 걸음이 섞임 → 걸음 수 비교는 공정하지 않음. 도착률만 비교
  - 경험치 59~81 (B2 63~77과 비슷) → 수풀을 피하지 않았고 전투도 그대로 함 (수풀 벌점 안 준 원칙 유지)
  - 비계 명시: 시연 경로(BFS), 세이브 상태 시작, 전투 자동, 마을 차단. RL: 경로 위 각 지점에서 걷는 법 (U턴, 수풀 주머니 탈출, 풀숲 지대) 을 도착 보상만으로
- **시드 재확인** (DEMO_TILE_route29_seed1, 같은 설정 시드 1. 시드 0과 같은 진단 실행)
