# SELFREPAIR (트랙 A, 초안 10-10): 실패를 스스로 감지 → 재탐색 → 재학습 → 다시 도전

> 장기 목표(최종 목표만 주고 AI가 스스로)로 가는 첫 단계. 외부 검토 5차(10-10) 제안 + 사용자 동의 방향
> 연구 질문: **"AI가 스스로 무엇을 모르는지 감지하고, 그것을 배우고, 다음 문제에서도 활용할 수 있나"**

## 왜 이것부터
- 부품은 이미 있음: 목표 조건 정책(M2A_r30), Go-Explore(8구간 경로 발견), 역방향 커리큘럼(발견 경로 → 100%, 2구간 × 2시드), 진단 도구
- 지금은 사람이 "새 구간 지정 → 탐색기 실행 → 학습 시작 → 평가"를 매번 함 → 이 연결을 감독기가 하게 만들면 사람 개입이 크게 줆
- 목표 설정 층보다 먼저: 하위 정책이 모르는 곳에서 막히는 걸 스스로 메우지 못하면, 상위가 목표를 잘 정해도 전체가 안 돌아감

## 구조 (처음엔 단순한 감독기, 큰 모델 없음)
1. **실행**: 정책에 목표 맵을 주고 걸음
2. **실패 감지 (사람이 정한 기준, 처음 버전)**: N걸음(예: 60) 동안 목표 맵 도착도 없고 새 칸도 거의 없음(진전 없음) → "이 목표를 이 지점에서 못 함"
3. **재탐색**: 그 시점 상태에서 Go-Explore (BFS/지도/거리표 없음, 목표 맵 진입만 판정) → 경로 + 아카이브
4. **재학습**: 지금 정책에서 이어서, 발견 경로로 역방향 커리큘럼 + **기존 구간 섞기**(망각 방지) → 정해진 예산
5. **검증**: 새 구간 고정 출발 / 경로 밖 (아카이브 칸) / 기존 구간 유지
6. **실행 재개**: 갱신된 정책으로 다시 도전

## 첫 시험 무대: M2b (자연스럽게 생김)
- M2A_r30은 31번도로·도라지시티를 본 적 없음 → 제로샷으로 막힐 것 (측정 예정) → 감독기가 스스로 메우나
- 사람이 하는 일 (명시): 최종 목표 맵 순서(30번도로 → 31번도로 → 도라지시티), 실패 기준 N, 예산, 이벤트 매크로
- **비교 기준**: 같은 구간을 지금 방식(사람이 구간 지정 + 탐색 + 학습)으로 했을 때의 성능과 사람 개입 횟수

## 지표
- 사람 개입 횟수 (명령 실행/구간 지정 수) — 줄어야 함
- 최종 도착률 (새 구간), 기존 11개 목표 유지 (망각), 경로 밖 도착률
- 비용: 탐색 걸음 + 학습 스텝 + 실패 감지까지 걸린 걸음
- 재사용: 두 번째 새 구간에서 적응 비용이 줄었나 (전이)

## 주의 (외부 검토 반영)
- Go-Explore 성공 ≠ 자율적 문제 해결. "왜 열렸는지(인과)"는 별도 검증 (예: 이벤트 플래그 실험에서, 발견한 행동을 다른 상황에 재사용하나)
- 원핫 목표를 0%의 원인으로 단정하지 않음 (ZS30은 본 적 있는 목표에서도 0% → 관측/상태 분포/경험 부족 쪽). 목표 표현 실험과 관측 실험은 분리
- 2구간 × 2시드는 "확장 가능성 확인된 초기 성과"로만 씀

## 사용자 의견 반영 (10-12, M2B 학습 중 — 실험 시작 안 함)
- 의견: "11구간 두 시드 + 통합 실행 → 제한된 환경에서 재사용 가능한 목표 조건 길 찾기의 근거는 쌓였음. 하지만 자율 플레이 에이전트는 아님. 전환점은 M2b 성공보다 처음 보는 구간에서 탐색 → 학습 → 실패 감지 → 재탐색의 자동화"
- **채택**: 전환점 = 자동화 (10-10 트랙 A 최우선 결정, 이 실험의 목적과 같음). 성과 지표를 "도착률"보다 **사람 개입 횟수 + 새 구간 적응 비용**으로
- **데이터로 보정**:
  - "외운 정책 vs 찾는 정책"은 **학습한 맵 안에서만** 근거가 있음 — GOAL2 빼둔 지역 시드 0 100% / 시드 1 71%, NM3 경로 밖 100% (두 시드). **처음 보는 맵은 0%** (ZS30, M2A_r30 → M2b 새 구간 제로샷 전부 0%). "재사용"은 본 목표 사이의 재사용이지 새 맵 일반화가 아님
  - **M2A_r30(11구간 모델)은 경로 밖을 한 번도 안 잼** (runs/diagnose에 기록 없음). 11구간 통과는 대부분 고정 출발(시연 경로 위) 결과 → M2a 모델에 대해선 "외운 게 아니다"의 직접 근거가 아직 없음. 또 M2A 학습이 경로 밖 시작 상태(offpath.pkl)를 쓴 구간은 같은 칸으로 평가하면 빼둔 시험이 아님 → 잴 때 빼둔 지역/칸을 구분
  - 통합 실행 성과는 비계 묶음 (BFS 시연 학습, 최종 목표 순서, 회복 규칙, 이벤트·전투 매크로, 규칙 걸음) + 게임 시계 영향 (같은 모델 10/10 vs 26/30)
- **자동화의 실제 빈칸 (이 실험이 풀어야 할 것)**:
  1. 실패 감지 기준이 없음 (지금은 사람이 진단 보고 판단)
  2. Go-Explore는 **세이브 상태 되돌리기**에 의존 (실제 플레이에선 못 하는 조작) → "자율 탐색"이라 쓸 때 명시
  3. **이벤트로 막힌 길은 위치 탐색으로 못 찾음**: route30_north가 막힌 원인 = 공박사 대화 누락 (10-10). Go-Explore 칸 = 위치라 "누구와 대화해야 열림"은 탐색 대상이 아님 → 셀에 이벤트 플래그/대화 기록을 넣는 것 등이 트랙 A 과제
  4. 새 구간을 정책 하나에 넣을 때 망각 (M2B 망각 검증이 첫 데이터)
  5. 목표 맵(원핫)과 구간 경계는 아직 사람이 줌
- **보류 (M2B 끝난 뒤 사용자 결정)**: M2A_r30 경로 밖 진단 (offpath.pkl 있는 M2a 구간, 평가만), E26 판정 기준 확정 (비교 기준 = M2b를 사람이 구간 지정 + BFS + 학습으로 한 M2B_multi의 성능과 사람 개입 횟수)

## 상태
- ✅ 설계 확정. **1단계 재현성 완료 (10-13, 10-14 재검증)**, **2단계 기준선 완료 (10-14)**. 3·4단계(학습)는 아직 시작하지 않음. 이 줄 아래 옛 메모는 초안 기록으로 남김
- (옛) ⬜ 초안. M2b 구간 준비 + M2A_r30 제로샷 평가 뒤 판정 기준 확정

### 첫 E26 범위 (하나만): 사람이 실패 원인을 판단하지 않아도 시스템이 실패를 감지하고 탐색·학습을 다시 시작하나
- 흐름: 기존 정책으로 새 구간 시도 → 실패 감지 (진전 없음 / 같은 위치 반복 / 예산 초과) → Go-Explore → 발견 경로로 학습 → 검증 + 기존 구간 망각 검사
- 경계 (명시): 목표 맵·구간 경계는 사람이 줌 → **완전 자율 플레이가 아니라 "주어진 구간 안의 자동 적응"**
- 무대 후보 M2b 구간에 이미 들어 있는 사람 도움: 시작 상태가 공박사 대화 뒤 (이벤트는 사람이 풀어 둠), 트레이너 잠김 = auto_event 매크로, 허용 맵(allowed_maps)

### 지표
| 지표 | 의미 |
|---|---|
| 사람 개입 횟수 | 시작 뒤 사람이 판단·조작한 횟수 |
| **미리 제공한 것** (필수 기록) | 목표 맵, 구간 경계·허용 맵, 시작 상태, 실패 감지 기준값, 예산, 매크로, 이벤트를 푼 상태 등 — 실행 중 개입 0회여도 이걸로 자율 수준을 판단 |
| 새 구간 적응 비용 | 성공 기준까지 Go-Explore 환경 걸음 (세이브 복원 포함, 따로), PPO 학습 스텝, 실제 시간 |
| 자동 복구율 | 실패 감지 뒤 개입 없이 목표에 도달한 비율 |
| 기존 구간 성능 유지 | 추가 학습 전후 기존 구간 길 찾기 실패율 변화 (시계 고정) |
- 비교 기준: 같은 M2b 구간을 사람이 구간 지정 + BFS + 학습한 M2B_multi
- 판정 기준 수치는 M2B 결과 뒤 확정 (지금은 설계 확장 안 함)

## 확정 설계 (10-12 밤, 결과 보기 전 — 사용자 지시 반영)

> 목표: 연구소 문을 빠져나가는 것 자체가 아님. **처음 보는 출발 상태에서 실패했을 때, 사람이 새 규칙을 쓰지 않아도 시스템이 스스로 해결 방법을 찾고, 기존 능력을 유지하면서 다시 진행하나**

### 질문과 가설
- **질문**: 경계 출발 상태(구간을 이을 때 생기는, 학습한 적 없는 출발점)에서 생긴 정책 실패를 자동으로 복구할 수 있나
- **가설 H-A (트랙 A)**: 실패 감지 → Go-Explore → 발견 경로로 이어 학습 → 재도전을 자동으로 이으면, 사람 개입 없이 실패 상태에서 복구되고 (≥ 80%) 기존 16구간 성능도 유지됨
- **비교 H-B (트랙 B)**: 사람이 설계한 방법 (통합 실행에서 구간 전환 상태를 모두 저장 → 학습 시작점에 추가 → 이어 학습)도 같은 수준으로 복구됨. 질문은 "A가 B만큼 되나, 비용은 얼마나 드나"
- 배경 (10-12 판정 3): 연구소 이벤트 뒤 문 밖에서 정책(구간 newbark, 목표 29번도로)이 연구소로 다시 들어감 → 실패 23판 중 22판. newbark 구간은 집 문 앞 출발만 학습함

### 공통 조건 (A, B 같게)
| 항목 | 값 |
|---|---|
| 초기 체크포인트 | `models/M2B_multi/final.zip` (읽기만, 덮어쓰지 않음) — 트랙 B 계보. A도 여기서 시작함을 결과에 명시 |
| 평가 상태 | `states/e26/eval/` (아래 2단계에서 만들고 고정, sha1 기록). **A·B 학습 데이터에 넣지 않음** |
| 이어 학습 예산 | PPO 15만 스텝, 기존 16구간 섞기 (m2b_multi 가중치 그대로) + 새 출발 쪽 가중치 3. 시드 0, 1 |
| 길 찾기 보상/관찰/정책 | M2B와 같음 (goal_only, tile, --goal, 256-256, fast-battle, auto-event) |
| 규칙·매크로 | **바꾸지 않음** (연구소 나가기 규칙의 약점도 그대로 둠 → 개선은 정책에서 나와야 함) |
| 게임 시계 | 평가는 항상 고정. 아침·낮·밤 3조건 (1단계에서 구현 확인. 안 되면 고정 1조건 + 그 사실 명시) |
| 격리 | A 결과물 `states/e26/a/`, `models/A_E26_*`; B 결과물 `states/e26/b/`, `models/B_E26_*`. 서로의 데이터·가중치 사용 금지. 평가 상태와 sha1이 같은 상태가 학습 데이터에 있으면 그 실행 무효 |

### 실행 순서와 단계별 판정
**1단계: 재현성 (코드만, 학습 없음)**
- 평가 기록 공통 함수: 코드 버전 (git 커밋 + 수정 파일 diff 해시), 게임 시계 조건·게임 시각 (HRAM 시각 값 읽어 검증), 시작 상태 sha1, 지나간 구간 목록, 실제 종료 위치, 판정 범위
- **무효 규칙**: 지나간 구간/최종 목표 맵이 의도한 범위와 다르면 그 평가는 무효 (오늘 "연구소에서 끝난 19/20" 같은 경우)
- 시간대: 세이브 상태 RTC 값을 바꿔 아침/낮/밤 3개를 만들고, 게임 안 시각 + 야생 출현 표로 확인. 확인 기준: 같은 상태·같은 시드 2번 실행 결과가 같고, 시간대마다 게임 시각 값이 다름
- 통과 조건: 기존 결과 하나 (M2B route30 시계 고정)를 새 기록 방식으로 다시 재서 같은 숫자가 나옴 (재현)

**2단계: 기준선 (모델·규칙 수정 없음)**
- 평가 상태 2종 고정 (만드는 실행의 시드는 A·B 실행과 다르게):
  - **E-lab**: 연구소 이벤트 + 공박사 대화 + 나가는 길 이벤트 뒤 연두마을로 막 나온 상태 (판정 3 실패 지점). 시간대 3개
  - **E-violet (전이 시험, 학습 금지)**: 도라지 센터에서 회복 매크로 직후 간호사 앞 (오늘 찾은 두 번째 미학습 경계, 같은 종류). 목표 도라지시티
- 평가 전용 구간 정의 (`newbark_labdoor`: 시작 E-lab, 허용 연두마을, 목표 29번도로 / `violet_pc_counter`: 시작 E-violet, 허용 도라지 센터, 목표 도라지시티). 연구소에 다시 들어가면 이탈 = 실패 (규칙 없이 정책만 잼)

- **전제 조건**: E-lab 기준선 실패율 ≥ 30% (오늘 통합 실행 기준 약 55%). 미만이면 실패가 상태 하나로 재현 안 되는 것 → 실험 재설계 (여러 경계 상태로)

**3단계: 트랙 B (경계 출발점 자동 수집)**
- 통합 실행 (판정 3과 같은 조건: `--targets "26,10;24,5;10,7" --no-heal-at 10,5`, 평가와 다른 시드) N=20판에서 **구간 전환 순간의 상태를 자동 저장** → (맵, x, y, 방향) 기준 중복 제거 → 그 구간의 학습 시작점 후보로 등록 (실제 출발 확률 안에서 섞음)

- 사람이 정한 것: "구간 전환 때 저장" 방식 자체, 수집 판 수, 중복 기준, 예산

**4단계: 트랙 A (자동 복구)** — 새 코드 `train/selfrepair.py`가 아래를 사람 없이 이음
1. **실행**: 통합 실행 (B와 같은 조건, 같은 시드 묶음)
2. **실패 감지** (규칙, 값은 사람이 미리 정함): 같은 목표로 300걸음 넘게 도착 못 함 / 60걸음 동안 새 칸 없음 / 떠난 맵으로 2번 이상 되돌아감. 감지 순간 상태 저장
   - 오경보 시험: 기존 16구간 정상 출발 각 25판에서 감지기가 울리는 비율 기록 (≤ 5%가 목표)
3. **탐색**: 감지 상태에서 Go-Explore (BFS·거리표·지도 없음, 목표 = 상위 계획이 준 다음 목표 맵) → 경로 (+ 상태들)

**5단계: 공정한 비교** — 같은 초기 체크포인트, 같은 평가 상태, 같은 PPO 예산, 같은 시드 수. 결과 표:

|---|---|

### 판정 기준 (결과 보기 전 확정)
- **H-A 지지** = 아래 모두, **두 시드 각각**
  1. 자동화: 4단계가 실행 중 사람 개입 0회로 끝남 (미리 제공한 것은 목록으로 따로)
  2. 복구: E-lab 길 찾기 실패 ≤ 20% (시간대 3개 각각)
  3. 보존: 기존 16구간 길 찾기 실패 모두 ≤ 20%, M2B 대비 +10%p 이상 오른 구간 없음
  4. 통합: 판정 3 ≥ 16/20 (시간대 각각)
- **부분 지지**: 1·2는 되고 3 또는 4가 안 됨 → "복구는 되나 보존/통합 실패"로 기록하고 원인 단계 표시
- **기각**: 1 또는 2가 안 됨 → 어느 단계에서 멈췄나 (감지 / 탐색 / 학습 / 재도전) 기록
- H-B도 같은 2·3·4 기준 (1은 해당 없음 — 사람 설계 방법)
- A vs B 비교에는 승패 기준을 따로 두지 않음 (같은 기준 통과 여부 + 비용/개입 표로 보고). E-violet 전이는 기준 없이 보고 (둘 다 낮을 것으로 예상, 높으면 그게 발견)
- 핵심 결론은 두 시드 모두로만. 대표 모델은 시드 0 (사전 지정)

### 위험과 대응
- E-lab 상태 하나에 과적합: 평가는 시간대 3개 + 여러 시드. 학습 데이터는 각자 자기 실행에서 얻은 상태만
- Go-Explore는 세이브 복원 사용 (실제 플레이에선 못 하는 조작) → 결과에 명시
- 감지 기준값·예산을 결과 보고 바꾸면 사후 조정 → 바꾸면 이 파일에 이유와 시점을 적고, 바꾸기 전 결과도 같이 보고
- 예상 시간: 1단계 반나절, 2단계 1~2시간, 3·4단계 각 시드당 학습 약 2시간 + 탐색/평가

### 설계 보강 (10-12 밤, 사용자 검토 반영 — 실행 전)
1. **실패 감지 초기값 채택** (300걸음 미도착 / 60걸음 새 칸 없음 / 떠난 맵 2회 재방문). 단 전투·대화·이벤트 중(전투 모드, 잠김 CF11 ≠ 0, run_event 처리 걸음)은 걸음 수에 넣지 않음. 감지마다 **원인(셋 중 무엇)**을 기록하고, 기존 16구간 정상 출발에서의 **오탐률**을 기록
2. **PPO 15만 = 최대 예산**. 분리 측정: Go-Explore 탐색 걸음 (세이브 복원 횟수 포함) / PPO 스텝 / 총 환경 걸음 (탐색 + 학습 + 평가) / 연산 시간 (단계별 실제 시간) / 사람 개입 횟수
3. **시간대**: 아침·낮·밤 설정이 구현되면 3조건 본 실험. 안 되면 고정 시각 1조건 제한적 실험 → **시간대 일반화 결론은 보류**
4. **E-lab 기준선 실패 분류**: 정책 실패 (정책 행동으로 목표 못 감: 이탈·시간초과) / 규칙 개입 실패 (매크로·규칙이 실패를 만듦) / 구간 전환 오류 (상위 계획·구간 선택·평가 범위 오류). **시스템 오류가 정책 행동을 막은 판은 H-A 기각이 아니라 실험 무효**로 분류 (판 단위 무효 사유 기록, 무효 비율이 높으면 그 평가 전체 무효)
5. **누출 검사**: sha1 같음 + **의미적 중복** (맵 ID, 좌표, 방향, 이벤트 플래그(스토리 진행 메모리), 목표 맵이 평가 상태와 같은 학습 시작 상태) 둘 다 검사. 걸리면 그 상태를 학습에서 빼고 기록. **E-violet은 전이 평가 전용으로 보존** (어떤 학습 데이터에도 같은 맵·좌표·목표 상태 없음을 검사)
6. **+10%p 기준은 운영상 판정 기준**이며 통계적 비열등성 증명이 아님 (25~50판 노이즈 약 ±10%p). 보고에 판 수와 신뢰구간을 같이 적음
7. **단계별 성과 기록**: 도착률 외에 ① 자동 감지 (실패를 감지했나, 원인, 오탐) ② 자동 탐색 (Go-Explore가 목표 경로를 찾았나, 걸음) ③ 정책 적응 (학습 뒤 E-lab 개선) ④ 무인 재도전 (사람 없이 다시 진행해 통과했나) 각각 성공/실패
