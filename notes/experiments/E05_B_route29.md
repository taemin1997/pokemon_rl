# B_route29 (A2 + 거리 shaping)

> 실험 기록 (가설, 판정 기준, 결과, 해석). 공통 조건은 `notes/04_experiments.md`

- **바꾼 것**: 보상만 (`--reward B_progress`). 환경은 A2와 같은 `--env route29`, PPO 설정도 동일
  - 추가 보상 = 0.1 × (이전 남은 거리 − 지금 남은 거리). 거리표에 없는 칸(점프 중간)은 건너뜀
- **구현 확인** (학습 전)
  - 제자리 B 연타 50걸음: shaping 0.00
  - 좌우 왕복 100걸음: shaping +0.10 (순이동 1칸만큼) → 농장 불가
  - 마을로 이탈: 보상 0
  - 정답 경로 따라가기: 185걸음 만에 도착, shaping +10.30 (= 0.1 × 103 정확히), 전체 보상 +21.7
- **가설**: A2가 U턴 이후에서 멈추는 이유가 "그 구간에 방향 신호가 없어서"라면, 거리 감소를 보상하면 무궁시티 도착이 생길 것
- **비교 대상**: A2_route29 250k (같은 학습량). 진단 평균 진행 S1 55, 무궁 0%
- **판정 기준** (250k 후 `diagnose_route29 --auto-battle`, A2와 같이 돌림)
  - 무궁시티 도착률 > 0%이고 진행 평균 > 55 → shaping 효과 있음
  - 진행은 늘었는데 도착 0% → 남은 구간에 다른 장애물이 있음 (위치 분석)
  - A2와 차이 없음 → 방향 신호가 병목이 아님 (학습량 문제 → A2 연장으로)
- **해석할 때 조심할 점**
  - 거리표는 **정답 지도(oracle)**. 잘 되면 "길을 찾았다"보다 "거리 신호를 따라갔다"에 가까움 → 나중에 shaping 없는 A2와 나란히 보여줘야 정직함
  - 거리표는 근사값 (같은 시작 상태로 BFS를 두 번 돌려 115/128이 나옴). 표가 틀린 곳에선 잘못된 신호가 감
  - `shaping_sum`은 항상 0.1 × (시작 거리 − 마지막 거리)여야 함. 아니면 버그
- **순서 메모**: A2 사전 기준은 "1M 연장"이었지만, 같은 250k 예산에서 B와 먼저 비교하고 나서 더 나은 쪽을 연장하기로 바꿈 (예산 효율)
- **결과** (250k, `final.zip` 기준. `train.diagnose`, 위치당 25판)

| 정책 | 시작 | 도착률 | 도착 걸음 | 진행 평균/최대 | 이탈 | 전멸 | 전투/판 |
|---|---|---|---|---|---|---|---|
| **B** | start (S1) | **64%** | 298 | 96.2 / 103 | 32% | 28% | 4.6 |
| **B** | S2 | 64% | 272 | 88.1 / 93 | 24% | 24% | 5.0 |
| **B** | S3 | 72% | 305 | 94.2 / 97 | 28% | 28% | 5.0 |
| A2 | start / S2 / S3 | 0% | - | 47 / 48 / 46 | 8~24% | 8~24% | 4~5 |
| random | start / S2 / S3 | 0% | - | 3 / 6 / 7 | 20~88% | 4~44% | 0~6 |

  - 최단 103걸음, 정답 경로 스크립트 185걸음 (방향 전환, 전투 포함)
  - 참고: 업데이트 1번 전 체크포인트(249,990)로 잰 값은 S1 68% / S2 48% / S3 68% → **25판 기준 ±10%p 정도는 판끼리 흔들림**. 실험 비교 때 이보다 작은 차이는 의미를 두지 않음
- **판정**: 도착률 0% → 68% → **shaping 효과 있음** (사전 기준 충족)
- **해석**
  - U턴 구간을 넘은 결정적 요인은 BFS 거리 신호 (A2와 차이). 이 부분은 "선생님(정답 지도) 덕분"이라고 명시해야 함
  - 플레이할 땐 거리표를 안 씀 (보상으로만 학습). 다만 29번도로 하나만 학습해서 길을 외웠을 가능성은 남아 있음 → 일반화 테스트 필요
  - **실패의 주원인은 이제 전멸**: 실패한 판의 거의 전부가 전멸 (S1 실패 36% 중 전멸 28%, S2/S3는 이탈 = 전멸)
  - **도착이 느림 (약 300걸음, 스크립트의 약 1.6배)** → 오래 돌아다닐수록 전투가 늘고(판당 4~5번) 회복이 없어서 전멸로 이어짐. 뜸 들이기(목표 앞 새 칸 훑기)가 실패로 직결되는 구조
  - 학습 지표(최근 도착률 100%)보다 진단(64~72%)이 낮음: 진단은 시작 프레임을 흔들어서 전투 타이밍이 달라짐 → 진단 숫자가 더 현실적임
- **다음**

  - B2 (`task`): 도착 보너스 + 거리 보상, 탐험 끔 → 도착 걸음이 줄면 전멸도 줄어야 함
