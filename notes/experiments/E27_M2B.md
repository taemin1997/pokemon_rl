# M2B_multi (트랙 B): M2a 11구간 + M2b 5구간을 정책 하나로 (30번도로 → 31번도로 → 도라지시티 → 체육관/센터)

> 공통 조건은 `notes/04_experiments.md`. 경로/이벤트는 `notes/07_m2a_story.md`. 사전 기록 10-10 16:5x (결과 보기 전)

## 왜
- M2A_r30은 새 구간을 전혀 못 감 (제로샷 0%, random도 0%) → 새 구간 학습 필요
- 외부 검토(10-10)가 본 세 가지: ① 연속 진행 (사람 개입 없이 도라지시티까지) ② 기존 능력 보존 (M2a 11목표 망각 여부) ③ 전투와 이동 결합 (트레이너에게 걸린 뒤 이동으로 복귀)

## 설정
- `--env m2b_multi --init models/M2A_r30/final.zip --reward goal_only --move tile --goal --hidden 256,256 --fast-battle --auto-event --steps 1000000 --name M2B_multi`
- 바꾼 것: 구간 11 → 16 (새 5개: route30_north 75, route31 60, violet_gym 31, violet_pc 10, violet_pc_exit 1), 새 길 3개 2배 가중, **auto_event** (잠기면 run_event — 통합 실행과 같은 처리, 인터페이스 비계)
- 시드 0. 초기 가중치 M2A_r30 (망각 측정이 목적이라 이어서). 주의: E25에서 GOAL2 계보 초기가 경로 밖 일반화를 손해 본 근거가 있음 → 경로 밖 결과 해석 때 감안
- 시연: BFS (`demo.pkl`) — 트랙 B. (트랙 A용 Go-Explore 경로는 3구간 준비됨, 학습엔 안 씀)

## 판정 (주)
1. **새 구간**: 5개 모두 길 찾기 실패율(전멸 제외) ≤ 20% (25판, route30_north/route31 50판)
2. **망각**: M2a 11구간 모두 길 찾기 실패율 ≤ 20% 유지 (M2A_r30 값과 나란히 보고)
3. **통합 실행**: 집 1층 → 할아버지 집 → 연구소(+공박사 대화) → 도라지체육관 문, 20판 중 ≥ 16 성공

## 결과 요약
- 학습 100만 스텝 완료. 새 5구간 길 찾기 실패 0~4% → 판정 1 통과
- 기존 11구간 실패 0~6%, 시계 고정에서는 0~4%. M2A 대비 +10%p 이상 악화 없음 → 판정 2 통과, 운영상 망각 징후 없음
- 통합 실행은 고정 시계 8/20, 실제 시계 9/20 → 판정 3 미달
- 실패 22판 중 21판은 연구소 문 밖의 미학습 출발 상태에서 재진입한 뒤 나가기 규칙도 실패한 경우. 연구소를 정상적으로 나온 판은 17/17 도라지체육관 도착

## 조건 변경: 전투 처리 (PP 0), 10-12 09:19 40만부터 (결과 보기 전)
- 원인 (10-11 19:23 확정): 자동 전투(A 연타)는 항상 1번 기술(할퀴기)만 고름 → PP 0이면 "기술의 남은 포인트가 없다!" → 기술 목록으로 돌아옴 → A → 무한 반복. 전투 상한(6,000/20,000프레임)에 걸려 에이전트에게 넘어가도 전투 중이라 같은 상황이 이어짐
- 수정 (`envs/battle.py auto_battle`, GoldEnv 자동 전투와 run_event 전투 둘 다 이걸 씀):
  - 1번 기술 PP가 남아 있으면 **예전과 똑같은 A 연타** (같은 타이밍)
  - 1번 PP가 0이 된 순간부터 B1 매크로(run_battle) + 규칙 `decide_pp_attack`: PP 남은 공격 기술(ROM 위력 > 0) 중 첫 번째. 공격 PP가 전부 0이면 야생은 도망, 트레이너는 남은 기술 → 발버둥
  - 기술 목록에 남은 상태(거절 뒤)는 '아래를 눌러 커서가 움직이나'로 진짜 목록인지 확인 (기술 고른 뒤 문구 중에도 블록이 남아 "moves"로 보이고 커서가 1로 읽혀서 헷갈렸음 — 첫 수정판이 이걸로 메인 메뉴에서 '포켓몬'을 열었음)
  - PP 주소: 파티 구조체 +0x17 = 최대 HP − 0x0D = `PARTY_MON1_PP` 0xDB3E (하위 6비트). stuck 상태 [0, 30, 20, 0], 연구소 [35, 30, 20, 0]으로 검증
- 확인 (`train.battle_eval`, 새 정책 `auto` = 실제 자동 전투 경로):

| 상태 | mash (예전) | auto (수정) | 판별로 같은 판 |
|---|---|---|---|
| route29 야생 30개 × 3 | 승 100%, 39.5초, 잃은 HP 3.7 | 승 100%, 39.5초, 3.7 | **90/90** |
| 라이벌전 × 5 | 승 100% | 승 100% | **5/5** |
| stuck_pp0 (멈춤 상태) × 10 | 시간초과 100% | **승 100%** (분노), 48초 | — |
| pp_low (route29 + 할퀴기 PP 1) 30 × 3 | 시간초과 99% | 도망 99%, 시간초과 0% | — |

  - pp_low 첫 수정판(공격 PP 없을 때 남은 기술 = 째려보기)은 시간초과 74%, 전멸 24% → 야생 도망 추가
- 같이 바꿈 (통합 실행만, 학습엔 영향 없음): 회복 규칙 `should_heal`에 "공격 기술 PP 0이면 센터" 추가
- 해석 주의: 40만까지 학습은 PP 0 전투가 안 끝나던 조건 (그동안은 프로세스 멈춤 → 감시가 재시작). 40만 이후는 PP 0이면 다른 기술/도망. 길 찾기 정책 입장에선 "PP 0 전투 뒤에도 이동이 이어짐"이 바뀐 것. 판정 기준은 사전 기록 그대로
- 평가: 학습 연쇄 (새 5구간 / 기존 11구간 / 경로 밖 / 통합 실행 20판) → 끝나면 POKE_RTC_LOCK=1로 같은 평가 (M2A_r30 vs M2B 같은 조건)
