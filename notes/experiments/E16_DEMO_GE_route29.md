# DEMO_GE_route29 (DEMO_TILE + 시연을 Go-Explore가 찾은 경로로)

> 실험 기록 (가설, 판정 기준, 결과, 해석). 공통 조건은 `notes/04_experiments.md`

- **바꾼 것**: 시연 파일만 (`--env route29_demo_ge`). 커리큘럼 규칙, 보상 `goal_only`, `--move tile`, PPO 그대로
- **시연 만들기** (`train/go_explore.py`, RL 없음): 가본 칸 아카이브에서 덜 뽑힌 칸을 골라 세이브로 돌아가 무작위로 최대 20걸음 (직전 방향 유지 0.7) → 칸마다 가장 짧게 온 기록만 남김 → 목표 맵에 닿으면 직전 칸을 따라 거꾸로 경로 추출
  - BFS 거리표, 목표 방향, 지도 모두 안 씀. 남는 비계: 칸 = 좌표, 세이브 상태, 전투 회피 (BFS 시연과 같은 방식 → HP 조건 같음)
  - 결과: 반복 2,167번(누적 4.3만 걸음)에 첫 도착 111걸음 → 다듬어서 **105걸음** (BFS 최단 103). 아카이브 492칸. 총 5.3만 걸음, 117분 (시드 1 학습과 CPU 공유)
  - BFS 경로와 105칸 중 64칸만 겹침 (평행한 줄, 다른 턱). HP 20 유지 (전투 0)
  - 비용 비교: BFS 약 2천 걸음 시험 vs Go-Explore 약 5.3만 걸음 → "정답 지도 없이" 찾는 값이 약 25배
- **가설**: DEMO_TILE의 성공이 "BFS 최단 경로"라는 특별한 시연 덕분이 아니라 커리큘럼 + RL 덕분이라면, 탐색으로 찾은 다른 경로로도 같은 수준이 나올 것
- **비교 대상**: DEMO_TILE (시드 0: 88/92/100%, 시드 1: 진단 예정)
- **판정 기준** (250k, `train.diagnose route29`)
  - S1/S2/S3 ≥ 80% → BFS 시연 불필요. **정답 지도 없이 M1** (비계: 좌표 칸, 세이브 상태, 전투 회피만)
  - DEMO_TILE보다 크게 낮음 (−20%p 넘게) → 시연 경로 모양이 중요함 → 경로 어디서 갈리는지(평행 줄, 턱) 분석
- **해석 주의**: 경로 길이가 거의 같아서(105 vs 103) "최단이 필요한가"는 약하게만 시험됨. 시험되는 건 "다른 경로 + 정답 지도 없음"
