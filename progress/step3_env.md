# 3단계: 골드 Gym 환경

**상태**: ✅ 계속 확장 중 (실험에 따라 옵션 추가)

## 목표
CartPole의 `gym.make()`가 해주던 일(관찰, 행동, 보상, 리셋)을 포켓몬용으로 직접 만들기
→ 1단계 PPO 코드를 거의 그대로 붙일 수 있게

## 기본 설계 (`envs/gold_env.py`)
| 요소 | 지금 | 이유 |
|---|---|---|
| 관찰 | 흑백 화면 72x80 | 벽, 길, NPC가 보여야 함. CPU 부담을 줄이려고 축소 |
| 행동 | 상하좌우 A B (6개) | START는 메뉴 낭비, 세이브 덮어쓰기 위험 |
| 1스텝 | 24프레임 (버튼 8 + 대기 16) | 1프레임 단위는 변화가 없어서 학습이 안 됨 |
| 리셋 | 시작 세이브 상태 (`_load_start`, 커리큘럼은 이것만 바꿔 끼움) | 오프닝을 매번 넘기는 낭비 방지 |

## 옵션 (기본값은 꺼짐 → 예전 실험 재현 가능)
| 옵션 | 하는 일 | 쓰는 곳 |
|---|---|---|
| `reward_cfg` | 보상 항목별 가중치 (새 칸, 새 맵, 배지, 거리 감소, 도착) | 모든 실험 (`train_ppo.py`의 `REWARD_PRESETS`) |
| `allowed_maps` / `goal_maps` | 구간 밖 = 실패 종료(그 걸음 보상 0), 목표 맵 = 성공 종료 | 구간 학습 |
| `auto_battle` | 전투를 A 연타로 자동 처리 (에이전트 걸음 1번) | 구간 학습 (길 찾기와 전투 분리) |
| `dist_path` | 거리표 → 진행도 기록, 거리 보상 | 구간 학습 |

## 커리큘럼 환경 (`envs/curriculum.py`)
| 클래스 | 시작 위치 고르는 법 | 결과 |
|---|---|---|
| `ReverseCurriculumEnv` (RC, RC2) | 목표 근처 씨앗에서 무작위 걸음으로 후보 확장 | ❌ 전선 정체 (확산이 느림) |
| `ArchiveCurriculumEnv` (AC) | 에이전트가 다녀본 좌표를 전부 후보로 (Go-Explore식) + 성공률 밴드 | 🔄 학습 중 |

## info로 나오는 게임 지표 (TensorBoard `game/`)
위치, 탐험 칸/맵 수, 배지, 전투 수, 경험치 증가, 전멸 수, 도착 여부, 도착 걸음, 이탈 여부, 진행(거리), shaping 합, 커리큘럼 후보 수, 실제 시작 도착

## 부족한 점
| 우선순위 | 내용 | 영향 | 해결 방향 |
|---|---|---|---|
| ~~높음~~ | ~~시작 상태가 하나뿐~~ | | 구간 시작 상태 + 커리큘럼으로 해결 |
| ~~높음~~ | ~~보상이 탐험뿐~~ | | 거리 보상, 도착 보상, 역할별 정리(`task`) |
| ~~중간~~ | ~~전투, 경험치 정보가 info에 없음~~ | | 추가함 |
| 보류 | 관찰에 기억 없음 (화면 한 장) | 진단상 현재 병목 아님 (막다른 길 가설 반증) | 필요해지면 가본 칸 지도를 두 번째 채널로 |
| 중간 | 전투가 A 연타 비계 | 체육관에선 질 수 있음 | 전투 모듈 (실행 층 + 판단 층) |
| 낮음 | 방향 전환 시 제자리 걸음이 생김 (버튼 8프레임) | 한 판에 약 30번 손해 | 누르는 프레임 16으로 (환경 실험) |
| 낮음 | 화면 축소가 단순 2칸 건너뛰기 | 작은 글자, 커서가 뭉개질 수 있음 | 전투 메뉴를 배워야 할 때 |
