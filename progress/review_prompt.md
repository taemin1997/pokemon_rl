# 외부 검토용 프롬프트 (2026-10-06 기준)

> 다른 AI/사람에게 의견을 물을 때 아래 블록을 그대로 붙여넣기. 숫자는 최신 결과로 고쳐서 쓰기

```text
포켓몬 골드(게임보이, 한국어판)를 강화학습으로 플레이하는 개인 프로젝트를 하고 있어. 지금까지의 실험 결과와 내 계획을 정리했으니 비판적으로 검토해줘. 동의보다는 틀렸거나 놓친 부분, 더 나은 방법을 찾아주는 게 도움이 돼.

## 목표와 원칙
- 최종 목표: 전당등록(챔피언까지). 단계 목표: M1 무궁시티 도착 → M2 첫 배지 → …
- 목적은 "AI를 만드는 것". RL 중심으로 가고, 규칙/BFS/세이브 스테이트는 RL을 가르치는 비계(scaffold)로만 씀 (보상 신호, 커리큘럼, 비교 기준선). 비계는 하나씩 걷어내며 효과를 측정
- 하드코딩 최소화: 게임 데이터는 메모리/ROM에서 읽거나 도구로 자동 생성
- 가장 먼저 원하는 능력: "길을 외우는 것"이 아니라 "길을 찾는 법"을 배우는 것

## 환경
- PyBoy 2.7, Gymnasium 1.3, Stable-Baselines3 2.9 PPO, CPU만 (환경 6개 병렬, 약 100~300스텝/초. 전투 자동 처리 시 느려짐)
- 관찰: 흑백 화면 72x80 한 장 (CnnPolicy). 좌표/방문 기록은 관찰에 없음
- 행동: 상하좌우 A B. 1스텝 = 24프레임 (버튼 8 + 대기 16)
- PPO: n_steps 512, batch 256, epochs 4, gamma 0.995, lr 2.5e-4, ent_coef 0.01
- 메모리 주소는 한국어판에서 직접 찾고 검증 (영문판 심볼과 구간마다 다르게 밀려 있음)

## 구간(segment) 구조
- 게임을 "시작 세이브 → 목표 맵" 구간으로 나눔. 구간 정의 한 줄 + 명령으로:
  - PyBoy로 갈 수 있는 칸을 BFS 탐색 → 칸마다 "목표까지 남은 걸음" 거리표 자동 생성 (턱 같은 일방통행 반영)
  - 거리표를 따라 걸어가서 목표 도착 상태를 저장 → 다음 구간의 시작 세이브로 자동 연결
- 구간 환경: 허용 맵 밖으로 나가면 실패 종료(그 걸음 보상 0), 목표 맵 도착 시 성공 종료, 최대 512걸음
- 전투는 A 연타로 자동 처리 (길 찾기와 분리). 전투 중 파티 HP 합이 0이 되면 전멸로 기록

## 29번도로 구간 실험 (입구 → 무궁시티, 최단 103걸음, 위치당 25판 진단, 오차 약 ±10%p)
| 실험 | 보상 | 무궁 도착률 | 진행(103 중) |
| v1 (집에서 시작, 2048걸음) | 새 칸 0.1 + 새 맵 1 | 0% (마을 복귀 100%) | 6 |
| A2 (29번도로 시작, 마을 이탈 = 실패, 전투 자동) | v1과 같음 | 0% (풀숲 통과 100%) | 약 47 |
| A3 | A2 + 도착 보너스 +10 | 0% | 약 48 |
| B | A2 + 거리 보상 0.1 x (이전 거리 - 지금 거리) | 64~72% | 약 95 |
| random | - | 0% | 약 5 |

발견한 것
- v1/v2가 멈춘 원인은 "막다른 길"이 아니라 마을 복귀 습관 + 풀숲 전투 비용 (진단으로 확인. 처음 세운 '막다른 길 기억' 가설은 거리표로 반증됨)
- A 실험에서 reward hacking: 구간 밖(마을)으로 나가는 걸음에 "새 맵 +1"이 붙어서 바로 나가기를 배움 → 이탈 걸음 보상 0으로 수정
- 남은 벽: 턱 줄의 유일한 틈으로 올라가 목표 반대 방향으로 9칸 가는 U턴 구간. 거리 보상 없이는 못 넘음
- 턱 38개 중 31개가 함정(뛰어내리면 목표에서 멀어짐) → 에이전트가 턱을 피하는 건 합리적으로 학습된 행동. 턱 없이도 도착 가능(+7걸음)
- B의 실패는 거의 전부 전멸. 도착이 느림(약 300걸음, 스크립트 185) → 목표 앞에서 새 칸을 훑으며 뜸 들임 (도착 = 종료라 새 칸 보상이 "끝내지 말라"고 함) → 그동안 전투가 늘어 전멸
- 같은 시작 상태로 BFS를 두 번 돌리면 최단 거리가 115/128로 다름 (돌아다니는 NPC 추정) → 거리표는 근사값

## 다음 계획 (후보)
1. 역방향 커리큘럼: 보상은 도착 보너스만(거리 보상 없음), 판마다 시작 위치를 절반은 실제 출발점(집), 절반은 BFS가 찾은 "갈 수 있는 칸" 중 무작위. 평가는 항상 집에서 시작. 범위는 집 + 마을 + 29번도로 전체, 목표 무궁시티
2. 관찰에 "가본 칸" 지도 채널 추가 (화면과 같은 좌표계로 두 번째 채널)
3. 여러 구간을 한 정책으로 학습 + 관찰에 목표 방향(메모리의 맵 연결 정보에서) → 학습 안 한 구간에 투입해서 일반화 측정
4. 보상 정리(task): 도착 +10, 거리 보상, 새 칸 보상 끔 → 뜸 들이기와 전멸 감소 확인
5. 전투: 행동을 묶어서(기술1~4, 교체, 아이템, 도망) 전투 전용 환경에서 RL. 규칙 기반(위력 x 자속 x 상성)을 기준선으로

## 질문
1. "길을 찾는 법을 배운다"를 증명하려면 위 계획(1→2→3) 순서가 맞는가? 더 직접적인 방법이 있나?
2. 역방향 커리큘럼(무작위 시작 + 도착 보너스만)이 정답 지도 없이 U턴 구간을 넘게 할 수 있을까? 실패한다면 어떤 이유일까?
3. 무작위 시작 위치를 "갈 수 있는 칸 전체"에서 고르면 정답 경로 정보가 안 들어가는데, 이 방식의 함정은? (예: 쉬운 칸만 많아서 학습이 치우침)

5. 여러 구간 일반화에서 "목표 방향" 관찰은 정당한가? 이게 사실상 답을 알려주는 건 아닌가?
6. 전멸 문제를 길 찾기 학습과 분리하는 게 맞나, 아니면 길 찾기 정책이 HP를 보고 판단하게 해야 하나?
7. 25판 진단의 ±10%p 오차를 고려할 때, 실험 비교를 더 효율적으로 하는 방법은?
```
