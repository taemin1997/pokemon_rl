# 게임 시계(RTC)가 실제 컴퓨터 시각을 따라감 → 실행 시각마다 게임 속 시간대가 달라짐 (10-10 16:2x 발견)

- PyBoy RTC: 세이브 상태에 저장된 기준 시각(timezero)과 **지금 컴퓨터 시각(time.time())의 차이**로 게임 시계를 계산 (`pyboy/core/cartridge/rtc.py`)
- 같은 세이브 상태라도 실행 시각이 다르면 게임 속 시각이 다름. 측정: 실제 16:21 → 게임 HRAM FF96/FF98/FF9A = 11:55:35 (추정 시/분/초, 오프셋 약 −4시간 26분). `rtc_lock_experimental(True)`면 8:21:15로 고정
- 금·은은 시간대(아침 4~10 / 낮 10~18 / 밤 18~4)마다 야생 포켓몬이 다름 → **전투 수·HP 소모·걸음 수가 실행 시각에 좌우됨**
- 발견 계기: M2A_r30 통합 실행이 07:49(게임 약 03시, 밤) 10/10·걸음 470~583 → 10:27~14:13(게임 아침~낮) 26/30·걸음 중앙값 960·전투 11~57번 → 16:12 같은 시드 2판도 또 다름
- 영향: 지금까지 모든 학습/평가가 실행 시각의 게임 시간대에서 진행됨 (밤새 학습 = 낮+밤 섞임). 같은 시드여도 시각이 다르면 재현 안 됨. 구간별 25판 평가도 시각에 따라 전투 수가 다를 수 있음
- 대응 (안): 평가에 게임 시각 기록 + 비교는 같은 시간대(또는 RTC 고정)에서. 학습은 시간대가 섞이는 게 일반화에 오히려 좋을 수 있어 바로 고정하진 않음 → 결정 필요
- 확인 필요: FF96 = 시(hour) 맞는지 (분/초와 함께 시간 흐름으로 검증)
- **10-10 23:4x 대응 1단계**: `POKE_RTC_LOCK=1` 환경변수면 GoldEnv가 시계 고정 (`rtc_lock_experimental`). 확인: route30 6판 두 번 → 걸음·전투 수 완전히 같음 (재현됨). 고정 시 게임 아침(약 8:21) → route30 평균 146걸음, 전투 3.5번 (시계 그대로였던 평가 90걸음보다 많음 = 아침 야생이 더 자주/길게)
- 사용자 결정 대기: 평가만 고정 / 학습도 고정 / 그대로 + 시각 기록. M2B 평가를 두 방식 모두로 돌려 근거 마련 (runs/locked_eval.log)
