# 전투 모듈 (트랙 2)

**상태**: 🔄 B1 완료, B2 규칙 준비 (29번도로에선 차이 없음 → 기술이 늘거나 트레이너 전투에서 검증)

## 왜 따로 하나
- 길찾기와 전투는 둘 다 필수. 보상 하나에 섞으면 보상끼리 싸움 (B의 뜸 들이기, "전투 점수 벌려고 풀숲 맴돌기" 위험)
- 정책을 나눔: 걷는 중엔 길찾기 정책, 전투 화면(`in_battle`)엔 전투 정책. 각자 자기 결과로만 평가
- 지금 전투 자리는 A 연타 비계 (`GoldEnv._run_auto_battle`). 이걸 단계별로 RL로 바꿈
- 길찾기 트랙(LAT1 등)과 따로 진행. 한 번에 하나만 바꾸기는 트랙 안에서 지킴

## 단계
| 단계 | 내용 | 상태 |
|---|---|---|
| 재료 | 메모리 주소 (적 HP, 메뉴 판별), 전투 시작 상태 | ✅ 10-07 |
| B0 기준선 | A 연타가 얼마나 이기나 (승률, 남은 HP, 턴 수, 전멸) — `train/battle_eval.py` | ✅ 10-07: 승리 100%, 잃은 HP 3.7/20 |
| B1 실행 층 | 묶은 행동 (기술 1~4 / 도망), 메뉴는 매크로 (`envs/battle.py`) | ✅ 10-07: 기술 1 매크로 = A 연타 (완전히 같음), 도망 100% |
| B2 규칙 판단 | "가장 센 기술" (위력 × 명중 × 자속 × 상성, ROM 표 `envs/rom_data.py`) | 🔄 구현. 29번도로는 할퀴기/째려보기뿐이라 기술 1과 같음 (100%) |
| B3 RL 판단 | 전투 전용 환경, 관찰 = 메모리 값 (HP, 레벨, 타입, PP), 보상 = 승패 + 남은 HP | ⬜ |

목표 시점: M2 체육관(비상) 전에 B2까지. 29번도로 야생은 A 연타로도 대부분 이김

## 재료
- 주소 (`envs/memory_map.py`, 검증 과정 `notes/02_memory_map.md`)
  - 적 HP / 최대 HP: D1BC / D1BE (2바이트)
  - 메뉴 블록 CEAD~CEB6: 시작 줄, 시작 칸, 행 수, 열 수, …, 커서 Y, 커서 X
  - `battle_menu(pyboy)` → "main" / "moves" / None. 야생 2전투 × 3턴 화면 대조에서 오판 0
- 전투 시작 상태: `uv run python -m train.build_battles route29 --n 30` → `states/battles/route29/` (30개, 56번 시도)
  - 적: 꼬리선(161) Lv2~3 16개, 구구(16) Lv2~4 13개, 꼬렛(19) Lv4 1개. 내 HP 18~20
- 전투 흐름 (화면 확인): 문구마다 A 필요 → 메인 메뉴 → 싸우다 → 기술 목록 → 공격 문구들 → (다음 턴) 메인 메뉴

## 모르는 것 / 확인할 것
- 기술 3~4개일 때 기술 목록 판별 (시작 줄 10 가정)
- 트레이너 전투 (전투 모드 2, 교체 문구 등), 가방/포켓몬 메뉴 안
- 레벨업 / 기술 배우기 문구 ("기술을 잊게 할까?" 예/아니오) — A 연타가 여기서 무엇을 고르는지

## B0 결과 (10-07, `uv run python -m train.battle_eval route29 mash --runs 5`)
전투 시작 상태 30개 × 5판 (판마다 시작 프레임을 흔들어 데미지/급소 난수를 바꿈)

| 정책 | 판 | 승리 | 전멸 | 시간 초과 | 턴 | 걸린 시간 | 잃은 HP (20 중) | 레벨업 |
|---|---|---|---|---|---|---|---|---|
| A 연타 | 150 | **100%** | 0% | 0% | 2.6 | 39.5초 | **3.7** | 27% |

| 적 (종, 레벨) | 판 | 턴 | 잃은 HP |
|---|---|---|---|
| 구구 Lv2 / Lv3 / Lv4 | 40 / 15 / 10 | 2.2 / 2.7 / 3.2 | 1.8 / 5.2 / 5.6 |
| 꼬리선 Lv2 / Lv3 | 35 / 45 | 2.1 / 3.0 | 1.9 / 5.2 |
| 꼬렛 Lv4 | 5 | 3.4 | 8.4 |

- **해석**
  - HP가 가득한 상태에서 시작한 전투 하나는 A 연타로 전부 이김. 29번도로 전멸은 전투 하나를 져서가 아니라 **회복 없이 연달아 싸워서 HP가 깎이는 것** (한 번에 평균 3.7, Lv3~4 상대면 5~8 → 3~4번 연속이면 위험)
  - 그래서 29번도로에서 전투 모듈이 줄일 수 있는 건 "이기기"가 아니라 **"덜 맞고 이기기"** (째려보기를 안 쓰는 게 맞는지, 약한 적에게 도망) 와 회복 판단. 체육관(M2)은 이기기 자체가 문제가 될 것 → 트레이너 전투 상태도 필요
  - 전투 하나 = 게임 시간 약 40초 = 걷기 약 59걸음 (한 걸음 40프레임). 라이브에서 "전투만 하는 것 같다"는 느낌의 원인
- **다음 (B1)**: 묶은 행동 실행 층. 행동 = 기술 1~4 / 도망. `battle_menu()`로 메인 메뉴/기술 목록 대기를 판별하고 커서를 옮겨서 고름. 확인용: "기술 1만" 매크로가 A 연타와 같은 결과(오차 안)여야 함

## B1 결과 (10-07, `train.battle_eval route29 mash move1 move2 run random best --runs 5`)
| 정책 | 승리 | 도망 | 전멸 | 시간 초과 | 턴 | 걸린 시간 | 잃은 HP |
|---|---|---|---|---|---|---|---|
| A 연타 (B0) | 100% | 0% | 0% | 0% | 2.6 | 39.5초 | 3.7 |
| **기술 1 (매크로)** | **100%** | 0% | 0% | 0% | 2.6 | 39.5초 | 3.7 |
| 기술 2 (째려보기만) | 0% | 0% | 28% | 72% | 7.6 | 96.8초 | 12.0 |
| 도망 | 0% | **100%** | 0% | 0% | 1.0 | 12.2초 | 0.1 |
| 무작위 (기술 80% / 도망 20%) | 5% | 95% | 0% | 0% | 2.0 | 23.9초 | 2.3 |
| best (B2 규칙) | 100% | 0% | 0% | 0% | 2.6 | 39.5초 | 3.7 |

- 매크로 확인: 기술 1 = A 연타가 판 단위로 똑같음 (같은 난수 타이밍) → 실행 층이 정확함
- 데미지 없는 기술만 쓰면 못 이김(시간 초과/전멸), 도망은 야생에서 거의 항상 성공 → 행동이 의도대로 먹힘
- best = 기술 1: 29번도로 리아코는 할퀴기(40)/째려보기(0)뿐이라 규칙이 고를 게 없음. **B2 효과는 기술이 늘거나(물대포 Lv13 전후) 상성이 갈리는 상대(트레이너)에서 검증**
- 고친 버그: 기술을 고른 직후에도 메뉴 블록 값이 잠깐 남아서 "거절됨"으로 오판 → B를 눌러 기술 선택이 취소됨 (기술 1만 써도 승리 0%). B를 안 누르게 고침
- 미처리: PP 0 거절, "기술을 잊게 할까?", 트레이너 교체 문구

## ROM 표 (`envs/rom_data.py`, 10-07)
- 주소를 박지 않고 표 맨 앞의 알려진 값(영문판과 같음)으로 검색. 각 패턴이 ROM에 정확히 한 번
  - 기술표 0x4172E (뱅크 0x10, 251개), 기본 능력치 0x51BDF (251종), 상성표 0x34D01 (110줄)
- 검증: 할퀴기 40/PP 35, 째려보기 효과 19, 몸통박치기 35/명중 95%, 리아코 물, 구구 노말/비행, 모다피 풀/비행, 물→불꽃 2배, 노말→고스트 0배, 전기→물/비행 4배

## 다음

## 트레이너 전투 상태 (10-07, 시도 중)
- 30번도로 구간(route30)을 만들었지만 트레이너 전투 상태는 아직 못 얻음
  - 탐색한 378칸 × 4방향에서 걸음 뒤 (A로 대화를 넘기며) 전투 모드를 봤는데 0만 나옴. 최단 경로 시연(60걸음)도 전투 0
  - 가능성: 트레이너 시야가 탐색 범위와 안 겹침 / 시야에 들어가면 대화 중 조작이 잠겨서 탐색이 그 칸을 "못 가는 칸"으로 처리 / 트레이너 전투의 전투 모드 값이 다름 (미검증)
  - 다음 방법 (하드코딩 없이): ROM의 맵 오브젝트 데이터에서 트레이너 위치와 시야 거리를 읽어서 그 줄로 걸어 들어가기. 또는 화면으로 트레이너 위치 확인
