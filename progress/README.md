## 목표와 원칙

**가장 큰 목표 (10-10, 사용자 결정): 장기 트랙 A — 사람은 최종 목표("전당등록")만 주고, AI가 중간 목표 설정 → 탐색 → 학습 → 실행까지 스스로 하는 포켓몬 AI**
- 트랙 B(전당등록 진행)는 그 과정의 실전 무대이자 기준선: 사람이 계획하고 AI가 실행. 트랙 B에서 사람이 맡은 칸(계획, 회복 판단, 이벤트 대처, 전투 판단)을 하나씩 AI로 바꾸는 게 트랙 A의 길
- 단계: (지금) 사람이 세부 목표를 주고 AI가 경로를 발견해 학습 → 목표 표현 일반화 (원핫 → 새 목표도 이해) → 스토리 진행(이벤트 플래그)까지 탐색으로 발견 → 기억/세계 모델 → 계층 RL (이동·탐험·대화·전투 조합) → **자율 목표 설정** (막히면 무엇을 해야 길이 열리는지 스스로)
- 트랙 B가 막힌 지점(예: 10-10 공박사 대화를 안 해서 30번도로가 막힘)은 트랙 A의 시험 문제로 쌓음 (정답을 알아서 검증 가능)
- 지금까지 만든 것(Go-Explore 탐색, 목표 조건 PPO, 상위 계획, 매크로)은 버리지 않고 이 시스템의 하위 능력/교체 대상으로 씀

**전당등록** (챔피언 목호까지. 관동은 범위 밖) = 트랙 B의 최종 결과물

| **두 트랙 운영** | (외부 검토의 H0/H1 = 우리 트랙 A/B. 통계 가설 기호와 헷갈려 A/B로 씀) **트랙 A 자율학습 연구**: BFS 없이 탐색, 처음 보는 맵 일반화, 자동 커리큘럼, 단일 정책 통합. 성공 기준 = 사람의 시연이 줄어도 새 지역 적응력 유지·향상. **트랙 B 전당등록 진행**: 이벤트, 전투, 회복, 배지, 장기 목표. 성공 기준 = 얼마나 멀리 가나 + 무엇을 자동화가 대신하나. 결과마다 트랙 표시, 둘을 섞어 "AI가 스스로 다 했다"고 주장하지 않음. **비계 제거보다 의존도 검증이 먼저** (BFS로 배워도 새 맵에서 길을 찾으면 됨). 비계는 "인터페이스 처리"(이름 입력, 대화 넘기기: 유지 가능)와 "의사결정 대체"(회복 판단, 선택지, 회복 장소 이동: 걷어낼 대상)로 구분. **기술은 A → B 한 방향으로 이식** (A에서 검증된 방법을 B에 가져감). **B의 BFS 경로/이벤트 정답 데이터는 A 학습에 넣지 않음** (A가 B 쪽 모델에서 시작하면 그 계보를 결과에 명시). 환경/관측/로깅/평가 코드는 공유. 표시: 모델 카드·실험 파일에 트랙, 로그 줄에 [A]/[B], 새 모델 이름 앞에 `A_`/`B_` | 10-08 |
