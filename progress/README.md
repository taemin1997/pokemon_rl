## 목표와 원칙

**최종 목표: 전당등록** (챔피언 목호까지. 관동은 범위 밖)

| 원칙 | 내용 | 정한 날 |
|---|---|---|
| **RL 중심** | 목적은 "AI를 만드는 것". 규칙/BFS/세이브 스테이트는 RL을 가르치는 **비계**로만 씀 (보상 신호, 커리큘럼, 비교 기준선, 임시 대체). 하나씩 RL로 넘기고 그때마다 성능 변화를 기록 | 10-05 |
| **선생님 없이 배우기 우선** | 거리 보상 없이도 배우는 방법(역방향 커리큘럼)을 주력으로. 거리 보상(B 계열)은 "통과 가능하다"는 증거이자 비교 기준 | 10-06 |
| **모델 하나가 여러 구간을** | 여러 구간을 한 정책으로 학습하고, 안 배운 구간에서 시험해서 일반화를 측정 | 10-05 |
| **확장성** | 게임을 구간으로 나누고, 구간 추가는 설정 한 줄 + 명령 | 10-05 |
| **하드코딩 최소화** | 게임 데이터는 메모리/ROM/도구로. 손으로 적는 건 검증용 정답과 진행 순서만 | 10-05 |
| **전멸은 지표로만** | 사람도 전멸함. 줄이는 작업은 따로 안 하고, 최종 플레이에선 센터에서 이어가기 | 10-06 |
| **수풀/전투에 벌점 안 줌** | 수풀을 피하게 만들면 레벨업도 안 함. 길 찾기 보상은 수풀에 중립으로 두고, 레벨업은 나중에 별도 목표(경험치 보상 구간)로. 전멸이 학습을 막으면 수풀이 아니라 "갇힘"을 고침 (조작 방식, 판 길이) | 10-06 |
| **모듈 분리 (길찾기 / 전투)** | 둘 다 필수. 보상 하나에 섞지 않고 정책을 나눔: 걷는 중엔 길찾기 정책(보상: 목표 도착), 전투 화면엔 전투 정책(보상: 전투 결과만). 어느 쪽을 쓸지는 상위 계획(지금은 `in_battle` + 구간 순서). 섞으면 B처럼 보상끼리 싸우거나 "전투 점수 벌려고 풀숲 맴돌기" 같은 구멍이 생김. 두 트랙은 따로 진행하고, 각 트랙 안에서 한 번에 하나만 바꿈 | 10-07 |
| **명시** | 무엇을 RL이 했고, 무엇을 규칙/사람 세이브로 처리했는지 항상 적음 | 10-02 |
| **정리하면서 가기** | 실험마다 notes(가설, 기준, 결과, 해석)와 progress를 바로 갱신 | 10-06 |
