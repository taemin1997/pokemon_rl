# 구간(segment) 현황과 추가 절차

> 확장성이 1순위. 게임을 "시작 상태 → 목표 맵" 구간으로 잘라서, 구간 하나를 추가하는 일이 **설정 한 줄 + 명령 몇 개**로 끝나게 함

## 구간 현황

| 구간 | 마일스톤 | 범위 → 목표 | 시작 상태 | 거리표 (최단) | 학습 | 진단 |
|---|---|---|---|---|---|---|
| newbark | M1 | 집 1층 → 29번도로 | `states/start.state` | ✅ 24걸음 | ✅ NB_scratch 100% (10만, 11분). 이어 붙여서 집 1층 → 무궁 96% | ✅ |
| route29 | M1 | 29번도로 → 무궁시티 | `states/eval/S1_entry.state` | ✅ 103걸음 | B2 88~96% (거리 보상) / AC 학습 중 (거리 보상 없음) | ✅ |
| route29_rev | 왕복 | 29번도로 서쪽 끝 → 연두마을 | route29 시연 마지막 칸 | ✅ 70걸음 (턱 지름길) | ⬜ GOAL1 | ✅ (시연 72, 경로 밖 395) |
| cherrygrove | M2 | 무궁시티 → 30번도로 | ✅ route29 `--harvest --avoid-battles` (HP 16/20) | ✅ 30걸음 | ⬜ | 시연 30 |
| route30 | M2 | 30번도로 (7,53) → 포켓몬할아버지 집 | ✅ cherrygrove 도착 상태 (HP 16) | ✅ 60걸음 (379칸) | ⬜ | 시연 60 (전투 0) |

## 새 구간 추가 절차

1. **이전 구간에서 도착 상태 만들기** (사람이 플레이할 필요 없음)
   ```bash
   uv run python -m train.build_segment <이전 구간> --harvest
   ```
   - 거리표를 따라 실제로 걸어가서 목표 맵에 들어간 순간을 저장함
   - 다음 구간의 시작 상태가 비어 있으면 자동으로 복사됨
2. **`envs/segments.py`에 Segment 한 줄 추가**
   - `allowed_maps`: 이 구간에서 돌아다녀도 되는 맵 (밖으로 나가면 실패 종료)
   - `goal_maps`: 도착하면 성공인 맵
   - 맵 번호는 `envs/map_names.py`나 pret 맵 상수표 참고
3. **거리표 만들기**
   ```bash
   uv run python -m train.build_segment <구간>
   ```
   - 시작 칸에서 목표까지 경로가 없으면 저장하지 않고 멈춤 → 스토리 이벤트나 `allowed_maps` 누락을 의심
   - 필요하면 `--check`로 결정성 확인 (같은 탐색 두 번, 거리 차이 칸 수)
   - (역방향 시연 학습용) `uv run python -m train.build_segment <구간> --demo`: 같은 길을 전투를 피해 걸으며 지나간 칸의 상태를 `states/segments/<구간>/demo.pkl`에 저장
4. **학습**
   ```bash
   uv run python -m train.train_ppo --env <구간> --reward task --steps 250000 --name <실험이름>
   ```
5. **진단 / 라이브**
   ```bash
   uv run python -m train.diagnose <구간> models/<실험이름>/final.zip random
   ```
   ```bash
   uv run python -m train.live_watch <실험이름> --env <구간>
   ```

## 알려진 문제
- **집 1층부터 한 번에 BFS를 돌리면 결과가 흔들림** (594칸 / 721칸, 경로 못 찾을 때도 있음. 구간별 BFS는 결정적). 평가용 긴 구간은 `compose`로 구간 거리표를 이어 붙여서 해결. 원인 미확인 (연두마을 NPC 위치나 실행 방식 차이 추정)
- ~~**이어 붙인 시작 상태가 이전 구간의 피해를 그대로 물려받음**~~ → `--harvest --avoid-battles` (10-07): cherrygrove 시작 HP 10 → 16. 예전 파일은 `*_hp10.state`로 백업
- **늦게 시작되는 인카운터** (10-07): 걸음 뒤 약 150~170프레임에 전투 모드가 켜짐. 기다림이 짧으면 "곧 전투가 시작될 상태"를 칸 상태로 저장 → 탐색이 막다른 곳으로 오판 (30번도로 18칸에서 멈춤). `SETTLE = 240`으로 통일 (거리표 탐색, 시연, 경로 밖 상태). 기존 route29 시연 1/103, 경로 밖 12/483이 이런 상태 → 평가 칸 비교를 지키려고 그대로 둠 (영향: 그 칸 시작 판에서 곧바로 전투 한 번)
- (원래 항목) 이어 붙인 시작 상태가 이전 구간의 피해를 그대로 물려받음: `cherrygrove/start.state`는 HP 10/20, 나무열매 없음 (29번도로 도착 상태를 만들면서 전투로 깎이고 나무열매를 먹음)
  - 그대로 학습하면 HP 반으로 시작해서 전멸이 잦을 것
  - 후보: `--harvest`를 여러 번 해서 HP가 가장 높은 도착 상태를 고르기 / 포켓몬센터 회복까지 구간에 포함 (회복 모듈의 첫 사례)

## 자동으로 안 되는 것 (사람이 해야 하는 것)

| 상황 | 이유 | 처리 |
|---|---|---|
| 스토리 이벤트로 길이 막힘 | BFS가 경로를 못 찾음 | 사람이 이벤트를 진행한 세이브를 시작 상태로 |
| 포획, 비전머신 사용, 기술 교체 | 깊은 메뉴 + 일회성 | 사람이 만든 세이브 또는 매크로 |
| 체육관 관장 등 강한 트레이너 | 자동 전투(A 연타)로 질 수 있음 | 전투 모듈 (Phase 4) |

## 공통 설정 (구간마다 같음)
- 보상 `task`: 목표 도착 +10, 거리 감소 걸음당 0.1, 새 칸/새 맵 보상 끔
- 전투: A 연타 자동 처리
- 최대 512걸음, 구간 밖으로 나가면 실패 종료 (그 걸음 보상 0)

## 관련 파일
- `envs/segments.py`: 구간 정의
- `train/build_segment.py`: 거리표 생성, 도착 상태 저장, 결정성 확인
- `train/diagnose.py`: 구간 공통 진단
- `train/train_ppo.py`: `--env <구간>`이 자동으로 생김
